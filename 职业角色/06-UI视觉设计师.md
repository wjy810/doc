# UI／视觉设计师进阶全景手册

> 从让一个页面清楚、协调，到为产品建立可扩展的视觉语言，再到用艺术指导塑造完整的品牌体验。  
> 版本：1.0 · 整理日期：2026-10-25  
> 适用对象：希望提升界面视觉质量的开发者、准备转向界面设计的平面与品牌设计师、需要自己完成视觉的独立开发者，以及希望系统提升的在职 UI／视觉设计师。

UI／视觉设计师要回答的核心问题是：用户在界面上先看到什么、怎样理解元素之间的关系，以及整个产品传递出怎样的气质。好的视觉设计不只是“好看”：它用层级引导注意，用对齐和间距表达分组，用颜色传达状态和语义，用一致的规则让用户在不同页面之间迁移经验，同时让品牌被记住。

本手册是职业角色系列中的一册，侧重视觉设计师的职责、方法与协作。版式、字体、色彩等视觉基础的练习，以及动效、三维和图形技术，见[《前端与 UI／UX 设计进阶全景手册》](../技术方向/前端与UIUX设计进阶全景手册.md)；交互与流程见[《UX／交互设计师》](05-UX交互设计师.md)。

主线是：**理解内容与品牌 → 建立视觉层级与版式 → 制定字体、色彩、图标与图像规则 → 设计组件与状态 → 系统化为设计令牌与主题 → 交付并检查实现 → 用艺术指导塑造整体体验。**

不同公司中，这一职责可能由 UI 设计师、视觉设计师、产品设计师、品牌设计师或设计系统设计师承担。本手册描述界面视觉设计的职责与方法；D1—D6 分级是学习组织方式，不对应任何职级体系。涉及字体、图片与 AI 生成内容授权的部分，只说明设计中需要注意的问题，具体权利与义务由法务确认。

## 第一篇：角色定位与能力坐标

<a id="ch01"></a>

### 01 UI／视觉设计师负责什么

#### 01.1 核心问题：让界面清楚、一致、有辨识度

视觉设计在界面中承担三项任务：

- **组织信息**：通过大小、粗细、颜色、间距和位置建立层级，让用户先看到最重要的内容，并理解元素之间的分组关系。
- **传达状态与语义**：可点击与不可点击、成功与错误、选中与未选中，都需要稳定、可感知的视觉表达。
- **表达品牌**：字体、色彩、图形和图像共同形成产品的气质，让用户产生信任和记忆。

视觉问题常被描述为“不够精致”“看起来乱”，但背后通常是具体的原因：层级不清、间距不一致、颜色承担了太多含义、组件状态缺失。视觉设计师的专业能力，体现在能把模糊的感受转化为具体的规则和修改。

#### 01.2 主要产出与质量标准

| 产出 | 用途 | 好的标准 |
| --- | --- | --- |
| 视觉方向与情绪板 | 对齐整体气质 | 与品牌和内容目标对应，有取舍说明 |
| 视觉规范 | 统一字体、色彩、间距、圆角、阴影、图标、图像 | 规则可执行，有适用范围和例外 |
| 高保真设计稿 | 表达最终界面 | 覆盖状态与真实内容，符合规范 |
| 组件视觉 | 统一各类组件的外观与状态 | 状态完整，对比达标，与令牌对应 |
| 图标与插画 | 辅助识别与表达 | 风格统一，小尺寸清晰，含义经过检验 |
| 设计令牌 | 把视觉决定传递给代码 | 命名表达用途，分层清楚，支持主题 |
| 切图与资源 | 供开发使用的图形资源 | 格式与尺寸正确，命名规范，授权清楚 |
| 视觉走查记录 | 检查实现与设计是否一致 | 问题具体，有截图与期望表现 |

#### 01.3 职责边界与相邻角色

| 事项 | 视觉设计师的位置 | 主要协作者 | 说明 |
| --- | --- | --- | --- |
| 信息结构与流程 | 参与 | UX／交互设计师主导 | 视觉层级需要服务于任务流程 |
| 界面视觉与组件外观 | 主导 | 交互设计师、前端开发者 | |
| 品牌识别 | 共同负责 | 品牌设计师、市场团队 | 品牌规范通常由品牌团队制定 |
| 文案 | 参与 | 内容设计师主导 | 文案长度会影响版式 |
| 动效 | 共同负责 | 交互设计师、动效设计师 | 视觉节奏与交互目的需要一致 |
| 设计令牌与组件实现 | 共同负责 | 前端开发者、设计系统团队 | 视觉决定通过令牌进入代码 |
| 可访问性 | 共同负责 | 无障碍专家 | 对比、颜色语义、焦点样式等从设计开始 |

#### 01.4 不同组织中的形态

- **产品设计师**：同时负责交互与视觉，常见于中小团队。
- **专职 UI 设计师**：在大团队中专注于界面视觉与组件。
- **品牌与营销设计师**：负责官网、活动页、广告与品牌物料，与产品界面相互协调。
- **设计系统设计师**：负责组件、令牌与规范的设计和维护（见 14 章）。
- **艺术指导**：统筹图像、插画、三维、动效等视觉表达的整体方向（见 10 章）。

**本章练习**：选一个你认为“看起来乱”的页面，找出至少 5 个具体原因（例如“同一层级的标题用了三种字号”），并分别写出修改规则。

### 02 能力坐标：横向分支与纵向深度

#### 02.1 十个横向分支

1. **视觉层级与版式**：层级、网格、对齐、间距与信息密度。
2. **字体与排版**：字体选择、字号层级、中西文混排与字体加载。
3. **色彩与主题**：颜色角色、对比、语义、深浅主题。
4. **图标与图形**：图标体系、图形语言与识别性。
5. **图像与插画**：图片选择、裁切、插画风格与授权。
6. **组件与状态视觉**：各类组件的外观与状态表达。
7. **设计令牌与系统化**：把视觉决定转化为可复用、可维护的变量。
8. **品牌与艺术指导**：把品牌特征转化为视觉规则并统筹多种媒介。
9. **数据可视化**：图表的视觉编码、颜色与可读性。
10. **交付与实现质量**：规格、资源、走查与跨平台适配。

#### 02.2 六级纵向深度

| 深度 | 视觉设计师的能力表现 | 典型证据 |
| --- | --- | --- |
| D1 理解与协助 | 能按规范完成页面，说明基本视觉原则 | 按规范完成的页面 |
| D2 独立完成 | 独立完成一个功能的完整视觉，覆盖状态与真实内容 | 高保真稿、状态视觉、走查记录 |
| D3 负责结果 | 为一个产品建立视觉规范并保持一致 | 视觉规范、组件视觉、令牌 |
| D4 系统与跨团队 | 协调多产品、多平台的视觉一致性 | 跨平台规范、多品牌主题 |
| D5 方法与机制 | 建立设计系统的视觉治理与质量机制 | 治理流程、视觉质量检查、培训 |
| D6 创新与影响 | 形成有影响力的视觉语言或方法 | 品牌体系、公开的设计系统、行业认可 |

#### 02.3 成长中的常见偏差

- 只用理想的示例内容设计，遇到真实数据就失去控制。
- 依赖装饰（阴影、渐变、特效）弥补层级问题。
- 每个页面单独设计，规则不能复用，越做越不一致。
- 只设计默认状态，悬停、焦点、禁用、错误等状态缺失。
- 忽视对比度和颜色语义，导致部分用户无法识别。

## 第二篇：核心工作方法

<a id="ch03"></a>

### 03 视觉层级、版式与网格

#### 03.1 建立层级的手段

| 手段 | 作用 | 注意 |
| --- | --- | --- |
| 大小 | 区分标题、正文、注释 | 层级之间的差异要足够明显 |
| 粗细 | 强调关键信息 | 同一区域内不要使用过多字重 |
| 颜色与明度 | 区分主次与状态 | 不只依靠颜色表达含义 |
| 间距 | 表达分组与节奏 | 组内间距小于组间间距 |
| 位置 | 引导阅读顺序 | 符合阅读习惯与任务顺序 |
| 对比 | 突出焦点 | 过多高强调元素会互相竞争 |

一个简单的检查方法是眯眼看或把页面模糊化：仍然能分辨出最重要的元素和主要分组，说明层级基本清楚。

#### 03.2 分组与格式塔原则

人会把相互接近、外观相似、位于同一区域或沿同一方向排列的元素看作一组。版式设计中，间距是最基本的分组工具：先用间距建立分组，再考虑是否需要边框或背景。过多的边框和分隔线常常是间距规则不清的信号。

#### 03.3 网格与间距尺度

网格提供对齐与节奏：列数、栏间距和外边距决定内容的排列方式。间距尺度（例如以 4 或 8 像素为基础的一组数值）让设计在各处使用有限的、成比例的间距，减少随意性。具体数值应根据内容密度、阅读距离和触摸操作调整，起步参考见[《前端与 UI／UX 设计进阶全景手册》第 23 章](../技术方向/前端与UIUX设计进阶全景手册.md#chapter-23)。

#### 03.4 信息密度

营销页面需要留白和节奏，工作台需要较高的信息密度。不要用同一种密度设计所有页面。高密度界面依靠对齐、清晰的层级和一致的行高保持可读，而不是简单地缩小字号和间距。

**本章练习**：把一个信息密集的页面重新排版，只调整字号、字重、间距和对齐，不添加任何装饰，比较修改前后的可读性。

<a id="ch04"></a>

### 04 字体与中文排版

#### 04.1 选择字体

选择字体时考虑：可读性（尤其是小字号和屏幕显示）、字符覆盖（简繁体、生僻字、多语言）、字重数量、与品牌气质的匹配、文件大小与加载方式，以及授权。中文字体包含数万个字符，文件通常较大，网页中常用系统字体、按需加载或字体子集化来控制体积。

#### 04.2 字体授权

商用字体需要按用途取得授权：网页嵌入、应用内嵌、印刷品、视频等可能是不同的授权范围。未经授权在产品中使用商用字体，可能带来侵权风险。开源字体通常更便于商用，例如 Adobe 与 Google 合作发布的思源黑体以 SIL 开放字体许可证发布，可以免费用于商业项目。[B01](#ref-b01) 使用任何字体前，都应确认授权文件中的具体条款。

#### 04.3 中文排版的要点

W3C 的《中文排版需求》系统整理了中文排版的规则与问题，包括标点符号的处理、行首行尾禁则、中西文混排、直排与横排等。[B02](#ref-b02) 界面设计中常见的要点：

- **行高**：中文正文通常需要比西文更大的行高，常见的起点是字号的 1.5 至 1.8 倍。
- **行长**：过长的行会让视线难以回到下一行开头，过短会频繁换行。阅读型页面应限制正文宽度，具体数值根据字号与阅读场景测试确定。
- **标点**：避免句末标点出现在行首，避免开括号、开引号出现在行尾。全角标点在连续出现时可以适当挤压。
- **中西文混排**：中文与西文、数字之间保留适当间距；为西文选择与中文风格协调的字体。
- **字号层级**：中文笔画复杂，过小的字号可读性下降，注释等小字号要实际检查。

#### 04.4 字号层级

建立有限的字号层级（例如正文、小标题、页面标题、注释），并为每一级规定字号、行高、字重和用途。层级之间的差异要足够明显；层级数量过多，反而会削弱层级。

**本章验收**：为一个中英文混排的页面制定排版规则，包括字体回退顺序、字号层级、行高、段落间距和标点处理，并用长段落、英文专有名词和数字检验效果。

<a id="ch05"></a>

### 05 色彩系统与主题

#### 05.1 颜色的角色

先定义颜色承担的角色，再为每个角色选择具体值：

| 角色 | 用途 | 注意 |
| --- | --- | --- |
| 品牌色 | 品牌识别与主要操作 | 不要同时用于错误或警示 |
| 背景与表面 | 页面、卡片、浮层的层次 | 层次之间的差异要可感知 |
| 文字与图标 | 主要、次要、禁用 | 每一级都要满足对比要求 |
| 边框与分隔 | 区分区域与控件边界 | 控件边界需要满足非文字对比 |
| 状态色 | 成功、警示、错误、信息 | 颜色之外还要有文字或图标 |
| 数据色 | 图表与可视化 | 见 11 章 |

#### 05.2 对比与色觉差异

《Web 内容无障碍指南》（WCAG）2.2 的 AA 级要求：正文文字与背景的对比度至少 4.5:1，大字号文字至少 3:1；识别界面组件和状态所需的图形（例如输入框边界、焦点指示、图标）与相邻颜色的对比度至少 3:1。[B03](#ref-b03) 此外，相当比例的人存在不同程度的色觉差异，最常见的是红绿色觉异常。因此，成功与错误不能只靠红绿区分，还需要图标、文字或形状。

#### 05.3 颜色空间与调色

CSS 颜色规范第 4 级引入了更多颜色空间，例如感知上更均匀的 OKLCH，便于生成明度一致的色阶，也支持比 sRGB 更广的色域。[B04](#ref-b04) 生成色阶时，以明度为主要变量调整，再检查对比；在不同显示设备上实际查看效果。

#### 05.4 深色主题

深色主题不是简单的反色。需要重新调整：表面层次（深色中通常用更亮的表面表示更高的层级）、品牌色与状态色的饱和度和明度、文字的对比、图片与插画的适配。每一组颜色在深浅两种主题下都要单独检查对比。

**本章验收**：为一个产品建立颜色角色表和深浅两套主题，用对比检查工具验证所有文字和控件边界，并模拟常见色觉差异检查状态表达。

<a id="ch06"></a>

### 06 图标、插画与图像

#### 06.1 图标体系

- **统一的网格与留白**：所有图标在同一尺寸的网格中绘制，保留一致的内边距。
- **统一的线宽、圆角与视角**：线性与面性图标不要混用在同一层级。
- **光学对齐**：数学上居中不一定看起来居中，圆形、三角形等需要视觉微调。
- **小尺寸检查**：在实际使用的最小尺寸下检查细节是否糊成一团。
- **含义检验**：除了极少数通用图标（如搜索、关闭），图标的含义并不总是被正确理解，重要操作应配文字标签。

#### 06.2 插画与图形语言

插画常用于空状态、引导、错误页和品牌传播。建立插画规范：风格、线条、色彩范围、人物表现方式（包括多样性与包容性）、使用场景和禁用场景。插画应服务于理解，而不只是装饰。

#### 06.3 图像的选择与裁切

图片要与内容相关，主体清楚，色调与整体协调。为不同屏幕规定裁切方式，确保主体和关键信息不被裁掉；为图片缺失、加载失败准备替代状态。人物照片要考虑授权与肖像权，产品截图要使用不含真实个人信息的数据。

#### 06.4 授权

图库图片、字体、图标库和插画素材都有各自的许可证，需要确认是否允许商用、修改、用于商标等。记录每个素材的来源与授权，以便日后核查。

**本章练习**：为一个产品设计 12 个图标，在 16、20、24 像素下检查清晰度，并请 5 人在不看标签的情况下说出含义，记录误解率。

<a id="ch07"></a>

### 07 组件视觉与状态

#### 07.1 组件的状态

| 状态 | 视觉要求 |
| --- | --- |
| 默认 | 清楚表明是否可操作 |
| 悬停 | 在支持指针的设备上给出反馈，不能是唯一的提示 |
| 焦点 | 清晰可见，满足非文字对比要求，不能被移除 |
| 按下 | 确认操作被接收 |
| 选中 | 与未选中有明显区别，不只依靠颜色 |
| 禁用 | 可识别为不可用，同时说明原因（必要时） |
| 加载 | 表明正在处理，防止重复提交 |
| 错误 | 与错误信息关联，清楚指出问题所在 |

#### 07.2 焦点样式

使用键盘的用户依靠焦点样式知道自己在哪里。很多设计因为“不好看”而去掉焦点框，这会让键盘用户无法使用产品。应设计一个与品牌协调、清晰可见的焦点样式，而不是删除它。

#### 07.3 密度与尺寸变体

同一个组件可能需要多种尺寸（例如紧凑、标准、宽松），适应不同的信息密度和输入方式。尺寸变化时保持比例与对齐关系，触屏上的可点击区域要足够大（WCAG 2.2 的 AA 级要求一般不小于 24×24 CSS 像素，或与相邻目标保持足够间距）。

**本章验收**：为按钮、输入框、复选框、下拉菜单设计完整的状态视觉，在深浅主题下检查对比，并只用键盘操作验证焦点样式。

<a id="ch08"></a>

### 08 设计令牌与主题化

#### 08.1 什么是设计令牌

设计令牌把颜色、字体、间距、圆角、阴影、动效时长等视觉决定保存为有名字的变量，让设计工具和代码使用同一套值。修改一个令牌，所有引用它的地方同步改变。设计令牌社区组在 2025 年 10 月发布了令牌格式模块的第一个稳定版本，定义了在不同工具之间交换令牌的文件格式；它是社区组报告，不是 W3C 正式标准。[B05](#ref-b05)

#### 08.2 分层与命名

常见的做法是把令牌分为三层：

| 层次 | 示例 | 作用 |
| --- | --- | --- |
| 基础令牌 | `blue-600`、`space-4` | 定义所有可用的原始值 |
| 语义令牌 | `color-action-primary`、`color-text-danger` | 表达用途，主题切换时改变它指向的值 |
| 组件令牌 | `button-primary-background` | 特定组件的值，按需使用 |

Material Design 3 也采用类似的分层，把令牌分为参考令牌、系统令牌和组件令牌。[B06](#ref-b06) 命名应表达用途而不是外观：`color-text-danger` 在深色主题中可以指向不同的值，而 `red-text` 会在颜色改变后变得名不副实。

#### 08.3 主题与多品牌

语义令牌是实现深浅主题和多品牌的关键：组件只引用语义令牌，切换主题时只改变语义令牌指向的基础值。新增主题时，逐一检查对比与状态表达。

#### 08.4 从设计到代码

令牌需要一条可靠的传递路径：设计工具中的变量导出为标准格式，再转换为 CSS 变量、移动端资源等。约定由谁维护、怎样评审变更、怎样通知使用者。

**本章验收**：为一个产品建立三层令牌，覆盖颜色、字体、间距、圆角和阴影，实现深浅两套主题，并与前端开发者一起完成一次从设计变量到 CSS 变量的同步。

<a id="ch09"></a>

### 09 交付与视觉走查

#### 09.1 交付什么

| 内容 | 说明 |
| --- | --- |
| 设计稿与状态 | 所有页面、组件状态、深浅主题、不同宽度 |
| 令牌与样式 | 引用令牌而不是写死的数值 |
| 资源 | 图标优先使用 SVG，位图提供合适的分辨率与格式 |
| 命名 | 资源与图层命名规范，便于查找 |
| 内容边界 | 长文本、空内容、图片缺失时的处理 |
| 授权信息 | 字体、图片、图标的来源与授权 |

#### 09.2 视觉走查

开发完成后，在真实环境中检查：字体与字重、颜色与对比、间距与对齐、图标清晰度、各状态与主题、不同宽度、长内容。走查问题要具体（位置、实际表现、期望表现、截图），并区分“必须修改”和“可以接受的差异”。

#### 09.3 自动化的视觉检查

截图对比测试可以在每次修改后发现意外的视觉变化，适合组件库和关键页面。它能发现变化，但不能判断变化是否合理，仍需要设计师确认（见[《前端与 UI／UX 设计进阶全景手册》第 17 章](../技术方向/前端与UIUX设计进阶全景手册.md#chapter-17)）。

**本章验收**：对一个已实现的功能进行视觉走查，整理问题清单，与前端开发者一起分析问题来源（规格不清、令牌缺失、实现差异）。

## 第三篇：专项与进阶

<a id="ch10"></a>

### 10 品牌表达与艺术指导

#### 10.1 从品牌特征到视觉规则

品牌特征（例如“可信、积极、清楚”）需要转化为具体规则才能被执行：

| 品牌特征 | 视觉规则示例 |
| --- | --- |
| 可信 | 克制的色彩，清楚的层级，真实的产品截图，不夸大的图像 |
| 积极 | 明亮的强调色，人物图片表现投入而非焦虑，插画有向上的动势 |
| 清楚 | 充足的留白，有限的字号层级，图标配文字 |

#### 10.2 情绪板与方向比较

在确定方向前，制作两到三个不同的视觉方向，用真实内容做关键页面，而不是只展示抽象的情绪板。比较时围绕品牌目标和用户任务讨论，记录取舍。

#### 10.3 艺术指导

艺术指导统筹多种视觉媒介：摄影、插画、三维、动效、视频。它为每种媒介制定规则（例如摄影的光线、构图、人物表现），并保持整体一致。艺术指导的价值在于让不同的人、不同的供应商做出的内容看起来属于同一个品牌（另见[《前端与 UI／UX 设计进阶全景手册》第 16 章](../技术方向/前端与UIUX设计进阶全景手册.md#chapter-16)）。

**本章练习**：为同一个产品做两个视觉方向，各包含首页、列表页和空状态，写出每个方向对应的品牌特征与规则，请 5 人描述感受并与设计意图对比。

<a id="ch11"></a>

### 11 数据可视化的视觉设计

#### 11.1 选择合适的编码

位置和长度是最容易被准确比较的视觉编码，面积、颜色深浅和角度的比较精度较低。因此，需要精确比较时优先使用条形图和点图，而不是饼图和面积图。

#### 11.2 数据颜色

| 数据类型 | 颜色方案 | 注意 |
| --- | --- | --- |
| 类别 | 区分明显的定性色板 | 类别过多时考虑分组或直接标注 |
| 顺序 | 从浅到深的单色或相近色阶 | 明度变化要单调 |
| 发散 | 两端不同色相、中间中性 | 中点要有实际含义 |

数据颜色同样需要考虑色觉差异与对比，并尽量直接在图上标注，减少对图例的依赖。

#### 11.3 图表的辅助元素

坐标轴、网格线、标签、单位、数据来源都应清楚但不抢眼。去掉不传达信息的装饰（三维效果、无意义的渐变）。

**本章练习**：把一个使用饼图和彩虹色的报表重新设计，说明每个改动对读者理解的帮助。

<a id="ch12"></a>

### 12 多平台与国际化

#### 12.1 遵循平台惯例

iOS、Android 和 Web 各有不同的导航方式、控件和交互习惯。Apple 的人机界面指南与 Google 的 Material Design 分别描述了各自平台的设计原则和组件规范。[B07](#ref-b07) 跨平台产品通常保持品牌与核心视觉一致，同时让控件与导航符合各平台的惯例。

#### 12.2 国际化

- **文字长度**：翻译后的文字可能比中文长很多，按钮和标签要能适应。
- **阅读方向**：从右到左的语言需要镜像布局与部分图标。
- **字体与字符**：不同语言需要不同的字体与回退策略。
- **文化含义**：颜色、手势、图像在不同文化中的含义可能不同，需要本地人员审查。
- **格式**：日期、数字、货币的格式随地区变化。

**本章练习**：把一个页面的文字替换为长度约为原文 1.5 倍的英文，检查哪些组件和布局需要调整。

<a id="ch13"></a>

### 13 AI 生成视觉内容

#### 13.1 适合的用途

AI 图像生成工具适合快速探索视觉方向、制作情绪板、生成占位图和草图。用于正式产品与品牌物料前，需要考虑以下问题。

#### 13.2 需要注意的问题

- **一致性**：生成的图像风格可能难以在多张图之间保持一致，需要艺术指导与后期调整。
- **准确性**：生成的人物、文字、手势、产品细节可能出现错误或不合常理的内容。
- **授权与权利**：不同工具的使用条款不同；各地对 AI 生成内容的著作权认定仍在发展；生成内容可能与已有作品相似。商业使用前由法务确认。
- **标识要求**：中国《人工智能生成合成内容标识办法》自 2025 年 9 月 1 日起施行，对生成合成内容的显式与隐式标识提出要求。[B08](#ref-b08) 发布 AI 生成的图像、视频等内容时，遵守适用的标识规定与平台规则。
- **偏见与刻板印象**：生成的人物形象可能强化刻板印象，需要审查多样性与包容性。

#### 13.3 记录与追溯

记录 AI 生成素材使用的工具、版本、提示词和后期修改，便于日后核查授权和复现风格。

**本章练习**：用 AI 工具为空状态插画生成三个方向，记录工具与提示词，检查一致性、准确性与刻板印象问题，最后说明是否适合正式使用以及需要的后期处理。

<a id="ch14"></a>

### 14 设计系统的视觉治理

#### 14.1 为什么需要治理

设计系统建立以后，最大的挑战是保持它的一致和有用：新需求不断出现，团队会创建“只用一次”的样式；旧组件没有及时更新；设计文件与代码逐渐不一致。

#### 14.2 治理的内容

- **贡献流程**：谁可以提出新组件或修改，怎样评审，怎样发布。
- **版本与变更通知**：每次变更说明影响范围，给使用者迁移时间。
- **一致性检查**：定期检查产品中偏离规范的样式，分析原因：规范缺失、规范不好用还是不了解规范。
- **淘汰机制**：旧样式与组件的弃用、迁移与删除。
- **度量**：组件采用率、偏离规范的数量、新页面的设计与开发时间。

**本章练习**：统计一个产品中实际使用的颜色值、字号和圆角数量，与规范对比，制定一个收敛计划。

## 第四篇：协作、实战与成长

<a id="ch15"></a>

### 15 与开发者的协作接口

#### 15.1 视觉设计师应提供给开发者的内容

| 内容 | 最低要求 | 常见缺失 |
| --- | --- | --- |
| 令牌与样式 | 设计稿中的值都对应令牌 | 大量写死的数值，与规范不一致 |
| 组件状态 | 所有状态的视觉 | 只有默认状态 |
| 主题 | 深浅主题各自的设计 | 只有浅色主题 |
| 响应式 | 不同宽度下的布局 | 只有一个宽度 |
| 内容边界 | 长文本、空内容、图片缺失 | 只用理想内容 |
| 资源 | 正确格式与命名，附授权信息 | 资源格式不对，来源不明 |

#### 15.2 开发者应反馈给视觉设计师的内容

实现困难或性能成本高的效果（例如大面积背景模糊、复杂阴影叠加）、组件库已有的能力与限制、不同浏览器与设备上的渲染差异、设计稿中不一致的数值。

#### 15.3 共同维护一致性

设计与代码使用同一套令牌和组件；新增样式先讨论是否已有可用的令牌；发现设计稿与代码不一致时，确认以哪一方为准并同步。

<a id="ch16"></a>

### 16 开发者怎样提升视觉质量

#### 16.1 最有效的几个习惯

- **使用有限的数值**：字号、间距、颜色、圆角各自只使用一小组值，定义为变量。
- **先用间距分组，再考虑边框**：多数“乱”的感觉来自间距不一致。
- **建立清楚的字号层级**：正文、小标题、标题、注释，层级之间差异明显。
- **颜色先定角色，再选具体值**：品牌色不要用于错误提示。
- **检查对比度**：使用对比检查工具，确保文字与控件边界达标。
- **对齐**：让元素沿有限的几条线对齐。
- **参考成熟的设计系统**：从 Material Design、Apple 人机界面指南或优秀的开源组件库中学习规则，而不是照搬外观。

#### 16.2 技术背景的常见偏差

- 每个页面单独调整数值，导致规则失控。
- 用默认的浏览器样式或随意的颜色值。
- 只在自己的屏幕和浏览器上检查。
- 认为视觉是“锦上添花”，在时间不够时首先被牺牲。

<a id="ch17"></a>

### 17 贯穿实战：求职平台的视觉体系

本章展示为一个产品建立视觉体系的过程。颜色与数值都是示意。

#### 17.1 品牌特征与方向

平台的主要用户是第一次求职的学生，他们普遍焦虑、缺乏经验；另一类用户是招聘方，看重效率。团队确定的品牌特征是“可信、积极、清楚”。比较了两个方向：“温暖插画风格”与“克制的专业风格”，用真实内容做了首页、简历分析结果页和招聘方后台三个页面，最终选择以克制的专业风格为主体，在学生端的空状态和引导中加入温暖的插画。

#### 17.2 规则

| 项目 | 规则 |
| --- | --- |
| 字体 | 系统字体优先，中文回退到开源中文字体；三级标题、正文、注释四级字号 |
| 颜色 | 品牌蓝用于主要操作；状态色单独定义；所有文字满足 4.5:1 的对比 |
| 间距 | 以 4 像素为基础的尺度；学生端宽松，招聘方后台紧凑 |
| 图标 | 24 像素网格，2 像素线宽，重要操作配文字 |
| 插画 | 只用于空状态与引导，人物多样，避免焦虑或夸张的表情 |
| 主题 | 浅色与深色主题，语义令牌统一切换 |

#### 17.3 简历分析结果页

结果页的视觉重点是让学生快速了解“哪里需要改、为什么、怎么改”：

- 每条建议用卡片呈现，问题、原因、示例三部分层级分明。
- 严重程度用图标加文字表达，不只依靠颜色。
- “基于旧版本”的提示使用中性的信息色，避免让学生误以为出错。
- 与交互设计师一起确定建议卡片的展开、收起与已处理状态的视觉。

#### 17.4 职业能力画布

能力画布包含节点与连线，视觉上需要区分目标、技能、任务三类节点，以及“已掌握”“学习中”“未开始”三种状态。类别用形状和图标区分，状态用填充程度和文字标签区分，避免同时用颜色表达两种维度。

#### 17.5 交付与维护

视觉规范以设计令牌的形式与前端共享；组件库中每个组件都有浅色、深色与全部状态的视觉；每次发布前进行视觉走查，关键页面有截图对比测试。三个月后统计偏离规范的样式数量，发现招聘方后台新增了 7 种不在规范中的灰色，经讨论补充为两个语义令牌，其余替换为已有令牌。

| C 体系负责 | 08、10—12 章 | 为一个产品建立视觉规范与令牌 | 新页面能快速保持一致 |
| D 治理与方向 | 13、14 章 | 负责设计系统视觉治理或艺术指导 | 他人能借助你的体系做出一致的视觉 |

#### 18.5 检查清单

- [ ] 层级清楚：模糊化后仍能看出重点与分组。
- [ ] 字号、间距、颜色、圆角只使用规范中的值。
- [ ] 文字与背景、控件边界与相邻颜色的对比达到要求。
- [ ] 状态不只依靠颜色表达。
- [ ] 组件的默认、悬停、焦点、按下、选中、禁用、加载、错误状态完整。
- [ ] 焦点样式清晰可见。
- [ ] 深浅主题分别检查过。
- [ ] 长文本、空内容、图片缺失有处理方式。
- [ ] 字体、图片、图标与 AI 生成素材的来源和授权已记录。
- [ ] 实现后完成视觉走查。

## 附录 C：常见误读、内容边界与修订记录

### C.1 常见误读与准确表述

| 容易误读的说法 | 更准确的表述 |
| --- | --- |
| 视觉设计就是让界面好看 | 视觉设计组织信息、传达状态、表达品牌，“好看”是结果之一 |
| 颜色越丰富越吸引人 | 颜色承担的含义越多越容易混乱，应先定义角色 |
| 加阴影和渐变显得更精致 | 精致感主要来自层级、间距与一致性，装饰不能弥补结构问题 |
| 去掉焦点框更美观 | 焦点框是键盘用户的必需信息，应设计而不是删除 |
| 深色主题就是反色 | 需要重新调整层级、饱和度与对比 |
| 开源字体可以随便用 | 需要阅读许可证条款，确认使用范围 |
| AI 生成的图片可以直接商用 | 需要确认工具条款、权利状况与标识要求 |
| 对比度达标就是无障碍 | 对比只是其中一项，还有颜色语义、焦点、目标尺寸等，完整要求见 WCAG 2.2。[B09](#ref-b09) |

### C.2 内容边界

本手册覆盖界面视觉设计的职责与方法，不展开品牌战略、印刷工艺、三维与动效技术。字体、图片和 AI 生成内容的授权与法律问题只说明需要注意的地方，具体以许可证条款和法务意见为准。

相邻角色的展开见本系列其他各册，总览见[《职业角色全景》](README.md)。
