# 前端与 UI／UX 设计进阶全景手册

> 从界面基础到创意前端、图形计算、设计研究与媒介创新。  
> 版本：1.1 · 修订日期：2026-10-25（初版 1.0：2026-10-20）  
> 适用对象：希望系统提升页面视觉质量、交互体验和创意实现能力的开发者与设计学习者。

本手册围绕三个问题展开：怎样把一个页面做得清楚、协调和精致；怎样进一步实现有表现力的动效、图形与空间体验；怎样在每个专业方向中继续横向拓展和纵向深入。内容覆盖界面实现、UI 与 UX、设计系统、创意编程、三维、技术美术、仿真、图形研究以及认知和美学，并配套练习、项目、验收方法与官方资料。

学习可以从普通网页开始。先完成一个内容真实、状态完整、手机端可用的页面，再逐步加入新的表达手段。一个成熟作品通常是多个方向共同作用的结果：版式决定信息怎样被看见，交互决定用户怎样完成任务，动效说明变化的关系，技术决定这些设计能否稳定运行。

文中的阶段是为了安排学习依赖而建立的参考结构。审美水平、工程能力、研究深度和原创性分别发展；高质量的二维界面可以有很深的专业要求，复杂三维技术也需要设计判断。每一个领域都可以形成长期专长。

## 01 使用说明与能力框架

### 1.1 先明确几个经常混用的概念

**前端开发**负责把内容、状态和操作呈现到浏览器等客户端，并处理布局、事件、数据、资源和运行性能。HTML 提供结构，CSS 决定布局与样式，JavaScript 或 TypeScript 管理逻辑；Vue、React 等工具帮助组织复杂应用。

**UI 设计**关注界面怎样表达信息，包括版式、字体、色彩、图标、图像、组件及其状态。它既涉及静态外观，也涉及系统的一致性。

**UX 设计**关注用户完成目标的整个体验：需求是否真实、入口是否找得到、步骤是否合理、结果是否容易理解、错误是否能够恢复。UI 是用户体验的重要组成部分，UX 的范围还包括流程、内容、服务衔接和研究验证。

**交互设计**负责定义用户动作与系统响应之间的关系。一个“上传文件”功能，需要考虑选择文件、拖入文件、格式校验、上传中、取消、失败重试、成功查看等状态及其转换。

**创意前端与创意编程**强调使用代码进行视觉和交互创作。代码可以驱动字体、图形、声音、数据、三维和物理规则，形成独特的表达方式。

**技术美术**连接美术制作与工程实现，常涉及材质、着色器、特效、资产流程和性能优化。不同团队对这一角色的职责划分会有差异。

**图形学与 HCI 研究**分别关注图像和交互背后的方法。图形研究可能开发新的渲染或重建算法；HCI 研究可能提出新的输入方式、协作机制或界面评价方法。

### 1.2 用四个维度判断成长

| 维度 | 应当观察的能力 | 可保存的证据 |
| --- | --- | --- |
| 视觉表达 | 层级、构图、排版、色彩和素材是否协调 | 方案比较、设计规范、实际页面 |
| 交互体验 | 用户能否理解并完成任务 | 任务流程、用户测试记录、错误恢复演示 |
| 工程实现 | 能否稳定运行并适应真实数据与设备 | 可运行项目、性能记录、兼容与无障碍检查 |
| 原创与研究 | 是否形成自己的规则、方法或发现 | 实验设计、对照结果、工具、论文复现报告 |

“代码写得复杂”“使用很多库”“画面很炫”只描述了作品的某些特征。判断品质时，应当回到目标：阅读页面应支持理解，工作台应支持高效操作，品牌页面应传达清楚的形象，艺术作品应形成可感受的表达。

### 1.3 横向与纵向怎样配合

横向拓展发生在同一问题周围。例如学习字体时，可以接触中文排版、字体设计、动态字体、可变字体、国际化和阅读研究。纵向深入则发生在一个分支内部：从调整字号，到理解字体度量与回退，再到制作自动排版工具。

跨领域组合形成具体作品。例如“可探索的学习地图”需要前端、信息设计、二维图形、交互和认知研究；“三维产品发布页”需要品牌视觉、模型、灯光、镜头、动画和性能管理。选择项目时先确定核心目标，再选择必要的组合。

### 1.4 本手册的使用方法

第一次阅读先看第 02、18、21 章，建立整体方向。随后选择一个当前最需要的领域，阅读对应专业章节，并完成第 22 章中的一个项目。每完成一个项目，用第 24 章检查质量，再回到第 26 章记录证据和下一步。

如果已经能够写 Vue 或 React，可以先检查自己的 CSS 布局、视觉判断和状态设计。对这些基础的补充往往能很快改善现有产品。暂时没有明确作品方向时，优先完成“界面工程、视觉设计、交互体验、动效”四条共同基础。

## 02 从基础到高阶的八个学习阶段

### 2.1 阶段总览

| 阶段 | 核心任务 | 典型成果 | 继续深入的信号 |
| --- | --- | --- | --- |
| S0 结构与样式基础 | 理解 HTML、CSS 和基本脚本 | 可阅读、可操作的响应式页面 | 能解释布局来源并独立修改 |
| S1 视觉品质 | 建立层级、间距、字体与配色规则 | 风格一致的多页面作品 | 能说明视觉选择与内容的关系 |
| S2 产品体验与系统化 | 完整设计流程、状态与组件 | 可用的工作台或业务系统 | 能处理真实数据和异常情况 |
| S3 动效与创意表达 | 控制时间、运动和二维图形 | 动态官网、交互故事、图形实验 | 动效有清楚目的并能稳定交互 |
| S4 三维与实时空间 | 理解场景、材质、镜头和资源 | 三维产品页、虚拟展览 | 视觉质量与设备性能能够兼顾 |
| S5 定制效果与复杂系统 | 开发着色器、生成规则与仿真 | 粒子系统、程序化场景、专用工具 | 能解释算法并控制参数与边界 |
| S6 方法研发与创作工具 | 深入图形算法、计算设计与工具 | 渲染模块、编辑器、研究复现 | 有对照、可复现流程和适用范围 |
| S7 原创体验与研究整合 | 联结艺术、认知、交互和媒介 | 原创视觉语言、研究原型、互动装置 | 有明确命题、作品和验证证据 |

这些阶段呈现常见依赖关系。视觉研究、用户研究和美学思考可以从 S0 就开始；学习 HCI 也无需先掌握渲染引擎。不同方向会在中途分流，并根据项目需要重新汇合。

### 2.2 S0 结构与样式基础

首先掌握语义化 HTML、盒模型、层叠规则、Flex、Grid、定位和响应式。配合基本事件、DOM 操作和数据结构，完成导航、表单、卡片和弹窗。练习时使用长标题、缺失图片和不同屏幕宽度，让结构经受内容变化。

这一阶段的横向空间包括文字排版、表单交互、浏览器调试、基础可访问性和资源加载。完成标准是能在不依赖固定截图尺寸的情况下实现页面，并知道一个元素为什么出现在当前位置。

### 2.3 S1 视觉品质

建立字号层级、间距尺度、色彩语义、图片比例和组件轮廓。对照多个参考页面时，逐项分析它们如何排列信息，而后用自己的内容重新设计。参考研究应当保留来源，使用素材时核对授权。

横向可以进入字体、摄影、插画、图标、编辑设计和品牌设计。成果应包含一套视觉规则与至少三种页面类型，证明这些规则能够支持不同内容。

### 2.4 S2 产品体验与系统化

学习任务分析、信息架构、操作流程、状态机、组件 API 和设计系统。一个按钮的视觉变化需要对应真实状态；一套表单需要支持说明、校验、错误恢复和提交反馈。此时开始把界面质量与用户任务联系起来。

横向可以扩展到内容设计、复杂数据表、权限视图、国际化、多端适配和设计协作。阶段项目应包含从入口到结果的完整任务，以及空数据、加载、失败和权限不足等情况。

### 2.5 S3 动效与创意表达

学习缓动、时间线、布局过渡、滚动关联、手势和 SVG 或 Canvas。先让操作反馈连贯，再设计品牌叙事和视觉实验。动画应支持暂停、反向和中途打断，并为减少动态效果的用户提供合适呈现。

横向可以进入动态排版、音乐可视化、交互图表、程序化海报和小游戏。阶段成果既要有录屏展示，也要有可操作版本，说明动画在哪种输入和状态下运行。

### 2.6 S4 三维与实时空间

掌握坐标、相机、几何、材质、光照、纹理、模型导入和场景交互。先把一个物体展示好，再处理完整环境。视觉设计同时涉及镜头构图、灯光层次、材质风格以及界面与三维内容的关系。

横向可以扩展到产品可视化、角色、建筑、数字展览、地图场景和 XR。需要同步记录模型大小、纹理资源、加载过程和实际设备表现，形成可交付的场景。

### 2.7 S5 定制效果与复杂系统

学习着色器、噪声、粒子、实例化、生成规则、基本物理模型和 GPU 计算。把一个复杂效果拆成输入、状态、更新、绘制四部分，并建立可调参数。流体和布料等方向涉及不同程度的数值方法，应按项目逐步学习。

横向可以扩展到程序化材质、群体行为、风格化渲染、交互艺术和美术工具。成果应说明效果可控到什么程度、性能瓶颈在哪里、哪些设备或输入条件需要简化。

### 2.8 S6 方法研发与创作工具

选择一个明确问题深入，例如如何减少透明材质的渲染成本，如何让节点编辑器支持复杂连线，或如何从照片构建可浏览的场景。学习论文、算法分析、实验设计、性能剖析和可复现工程。

横向可以进入几何处理、逆向渲染、场景重建、可视化工具、自动布局和人机共创。研究项目要有基线、变量、评价方法和限制描述。复现公开方法与提出原创方法是不同成果，应清楚说明。

### 2.9 S7 原创体验与研究整合

围绕一个有价值的体验命题，组合艺术方向、交互机制、技术原型和研究证据。例如让人通过操作理解一组复杂关系，或让实体材料成为数字信息的表达方式。作品的目标、视觉语言和交互规则需要相互支持。

横向可以进入新媒体艺术、空间计算、协作媒介、知觉研究、设计哲学和创作工具研究。进入这一阶段以后，仍然需要回到字体、布局、反馈和运行质量等具体问题。

## 03 前端界面工程

### 3.1 研究对象与先修要求

界面工程把设计意图转化为稳定的交互界面。基础是 HTML、CSS、JavaScript；在项目变复杂后补充 TypeScript、组件框架、状态管理与构建工具。视觉还原只是起点，长期内容变化、设备差异和异常状态都会影响品质。

### 3.2 八个横向分支

1. **布局与响应式。** 研究内容如何在不同可用空间中重排，包括 Flex、Grid、容器尺寸、内在尺寸和定位。需要知道哪些区域允许压缩、换行、折叠或转为列表。对真实内容设计断点比只按某几款设备宽度照搬更可靠。
2. **字体与排版工程。** 处理字体加载、回退、字重、行高、字距、断行和中英文混排。字体文件尚未加载时，页面仍应可读；字体切换造成的布局移动也需要观察。横向可进入可变字体、多语种排版和阅读器。
3. **CSS 视觉表达。** 运用背景、渐变、阴影、边框、滤镜、遮罩、裁切和混合模式构建风格。每一层装饰都应有可解释的作用，例如分组、深度、焦点或品牌特征。需要检查效果叠加后的文字对比与运行成本。
4. **组件结构与接口。** 设计按钮、输入框、菜单、弹窗、表格等组件的属性、事件和状态。组件应允许内容变化，并保持键盘、触屏和屏幕阅读器语义。外观变体与业务逻辑应能合理组合。
5. **应用状态与数据表现。** 管理筛选、排序、分页、编辑草稿、加载和错误。优秀的页面能让用户理解目前看到哪份数据、操作是否已经生效、下一步能做什么。可以继续学习状态机和异步交互。
6. **资源与渲染性能。** 研究图片尺寸、字体资源、脚本拆分、列表规模和重绘成本。先观察真实慢点，再选择优化。效果较复杂的页面应为资源未准备好和设备能力较弱时设计完整状态。
7. **多输入与可访问实现。** 保证焦点顺序、键盘操作、表单标签、语义关系、触摸目标和内容替代方式。鼠标悬浮可以增加细节，关键操作应有其他可达方式。
8. **调试与质量保障。** 使用开发者工具检查布局、网络、性能和可访问性。对核心操作、历史问题和高风险逻辑保留适当测试，同时进行人工视觉检查。项目交付后还需要关注真实使用中的错误。

### 3.3 纵向深入示例

以卡片列表为例：先实现固定内容，再支持长短文本与图片比例变化，然后增加筛选与空状态，接着处理大量数据与键盘导航，最后形成稳定的组件接口和可视化示例。每一次深入都围绕真实需求增加能力。

### 3.4 练习与验收

制作一个资源列表页，包含搜索、分类、排序和详情。准备长标题、空结果、加载失败、缩略图缺失等数据。验收时改变窗口宽度、只用键盘操作、重复切换筛选，并观察页面是否丢失上下文。保存一份组件清单和异常状态截图。

参考入口：[MDN 核心课程](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core)。

## 04 视觉设计与品牌表达

### 4.1 研究对象与先修要求

视觉设计安排用户先看见什么、怎样理解关系，以及页面传递怎样的气质。需要逐步建立观察和比较能力：识别字号、对齐、边距、留白、明暗、图片比例和视觉重心。制作工具可以按当前习惯选择，最终应能解释设计取舍。

### 4.2 八个横向分支

1. **版式与构图。** 学习网格、对齐、节奏、视觉平衡和内容密度。先按内容建立分组，再决定分栏。长文、仪表盘和营销页面的信息量与阅读方式不同，需要各自的布局逻辑。
2. **字体设计与字体应用。** 观察字形气质、笔画、字面率和字重关系，学习标题、正文、注释与数字的搭配。横向可进入中文字体、拉丁字体、动态字体和编辑设计。关键是让字体支持内容及品牌。
3. **色彩系统。** 区分品牌色、内容色、状态色、背景与交互强调。建立颜色角色，再为不同主题选择具体值。颜色还要结合亮度、对比和语义使用，避免同一种颜色同时承担互相冲突的含义。
4. **图标与符号。** 统一线宽、视角、圆角、细节密度和视觉重量。研究用户能否识别图标含义，并为模糊符号提供文字标签。小尺寸图标需要专门检查，细节在缩小时可能丢失。
5. **摄影与图像编排。** 选择主题、光线、裁切、视线方向和色调协调的图片。应提前设计不同屏幕下的裁切方式，保护主体和关键信息。产品截图、人物摄影和氛围图片的表达任务也不同。
6. **插画与图形语言。** 探索几何、手绘、拼贴、纸感、三维插画和纹理。将图形语言应用到空状态、引导、专题和品牌识别中，并检查它与正文和交互组件是否协调。
7. **品牌识别与艺术方向。** 把品牌希望传达的特征转化为字体、色彩、图像、声音和运动规则。建立多种概念方案，通过实际页面比较。品牌的一致性需要允许内容变化，同时保留核心识别特征。
8. **信息与数据设计。** 根据比较、趋势、分布、关联等任务选择图表或图形。图表标签、单位、来源和不确定性应清楚；装饰应帮助辨认信息。此方向可继续深入地图、科学可视化和交互解释。

### 4.3 把审美练习变成可积累的材料

每周选择少量高质量页面，记录其内容目的、版式骨架、字体关系和图片处理。尝试用同一份内容做两种风格，比较各自适合的场景。参考库应写明“值得学习的具体地方”，以便以后迁移，而不是只保存截图。

### 4.4 练习与验收

为同一个产品做简约、编辑设计、科技三种方向。每种方向提供首页、详情页和空状态。比较文字是否易读、主次是否明确、素材是否统一、不同页面是否保留识别特征。最终选择一个方向，写出颜色角色、字体层级、间距和图片规则。

<a id="chapter-05"></a>
## 05 产品交互与用户体验

### 5.1 研究对象与先修要求

UX 工作从用户想完成的事情开始。了解任务发生的环境、已有做法、困难和成功标准，再设计流程与界面。前端开发者可以从身边的真实任务入手，用简单原型验证理解，逐步学习访谈和可用性测试。

### 5.2 八个横向分支

1. **用户与任务研究。** 观察用户实际怎样做事，区分事实、表达的愿望和设计者的推测。记录触发条件、频率、工具、输入和结果。研究结果应能指导范围与优先级。
2. **信息架构。** 组织分类、导航、层级、标签和搜索。用户可能按项目、时间、类型或目标寻找内容，因此需要根据任务选择组织方式，并测试命名是否容易理解。
3. **任务流程。** 设计从入口到结果的步骤，处理跨页面、跨设备和中断后恢复。每一步说明为什么需要信息、处理多久、结果在哪里。复杂流程适合用状态和条件描述。
4. **复杂操作。** 深入选择、批量编辑、拖拽、吸附、缩放、撤销和快捷键。操作反馈应显示影响范围，用户应能够理解并修正结果。编辑器和工作台通常需要这一分支。
5. **反馈与错误恢复。** 明确系统当前状态、执行结果以及可以采取的下一步。错误信息应指出可处理的问题，并尽量保留用户输入。加载、取消、重试和回退需要放在同一流程中考虑。
6. **内容与微文案。** 设计按钮标签、说明、提示、空状态和确认信息。用用户熟悉的对象与动作命名，并使同一个概念在各处保持一致。文案长度会影响布局，应和视觉设计一起验证。
7. **服务与多端衔接。** 把网页与邮件、通知、客服、线下服务及其他终端联系起来。状态变化应能跨入口解释清楚，用户返回时应知道任务进度。学习范围可扩展到服务蓝图与流程设计。
8. **评价与迭代。** 通过代表性任务观察成功、错误、耗时和困惑点，并结合主观反馈。少量定性测试适合发现问题，统计性结论需要相应的研究设计与样本。记录改动前后的证据。

### 5.3 练习与验收

选择“上传资料并得到分析结果”作为任务，设计文件选择、校验、处理、结果、失败重试、取消和历史记录。让使用者在没有口头指导的情况下尝试。记录他们犹豫的位置和理解错误，优先修正阻碍任务的原因。

### 5.4 与视觉的连接

UX 决定需要表达哪些状态，UI 决定这些状态如何被看见，工程负责状态真实发生。三者应共享同一份任务模型。只展示成功状态的设计稿，很难说明产品在真实使用中是否完整。

<a id="chapter-06"></a>
## 06 动效与时间设计

### 6.1 研究对象与先修要求

动效设计处理界面在时间中的变化，包括用户注意到变化的方式、元素移动的关系和操作的连续性。先理解 CSS 过渡、变换和关键帧，再学习时间线、手势、布局动画和状态控制。多数产品动效应服务于反馈、解释关系或组织注意力。

### 6.2 八个横向分支

1. **微交互。** 围绕一次小操作组织触发、过程和反馈，例如收藏、复制、切换、提交。状态变化需要与实际结果一致。复制成功动画应在复制完成后出现，失败时应提供可理解的替代操作。
2. **布局与共享元素过渡。** 让列表重排、卡片展开、详情进入等变化保持对象连续性。研究位置、尺寸和内容怎样同时变化，并处理元素被移除、重复打开和快速切换的情况。
3. **运动规律。** 使用缓动曲线、弹簧、惯性和阻尼安排运动。物体的尺寸、移动距离和任务紧迫程度会影响节奏选择。持续时间是设计参数，应结合设备、距离和使用场景验证。
4. **手势与直接操纵。** 研究拖拽、滑动、缩放、旋转以及松手后的行为。用户操作期间应保持响应，手势结束后清楚表达结果。考虑触屏与页面滚动的冲突，以及鼠标和键盘的替代路径。
5. **动态排版。** 使用文字分段、路径、遮罩、字形变化和节奏表达内容。正文和重要信息应保留可读、可选择的呈现。标题特效需要检查中文字符、长文本和减少动态效果的模式。
6. **滚动叙事与镜头编排。** 将滚动位置与章节、画面或模型变化联系起来，规划进入、停留和退出。要明确滚动是在浏览内容还是在控制演示，并保留清楚的进度和导航。
7. **声音与运动配合。** 把音效、音乐节拍和视觉事件联系起来。声音的触发、音量、开关和静音状态应由用户理解和控制；关掉声音后，主要信息仍应完整。
8. **动画状态与运行质量。** 管理暂停、取消、反向、队列和中断。检查页面不可见时的执行、动画对象的清理以及多个效果同时运行的表现。为用户的动态效果偏好提供合适的简化。

### 6.3 练习与验收

给一个列表到详情的流程增加动效：选中卡片、展开详情、编辑内容、保存、返回列表。连续快速点击并切换方向，观察内容和动画是否脱节；使用触屏和键盘测试；开启减少动态效果偏好后检查信息是否仍然清楚。

### 6.4 工具位置

CSS 适合许多简单过渡。Motion 和 GSAP 可帮助组织更复杂的动画与交互，但选择前应先写清楚状态和节奏。动画库解决实现与编排问题，动效设计负责决定什么应该动、怎样动以及何时结束。

参考入口：[Motion](https://motion.dev/docs)、[GSAP](https://gsap.com/docs/v3/)。

<a id="chapter-07"></a>
## 07 创意编程与二维图形

### 7.1 研究对象与先修要求

创意编程用代码组织图形、数据和输入，适合交互海报、绘画工具、动态图案和解释性作品。先学习坐标、循环、函数、向量和事件，再理解 SVG、Canvas 与 DOM 各自的表示方式。选择表现形式时同时考虑交互数量、图形规模和可访问内容。

### 7.2 八个横向分支

1. **矢量路径与曲线。** 研究直线、贝塞尔曲线、路径插值、描边和形状变换。适合标志动画、流程关系、路径编辑和图解。复杂路径变化需要处理点的对应关系，避免不受控的跳变。
2. **画布与笔刷。** 深入 Canvas 的绘制、坐标变换、透明度、合成和像素处理。可以制作画板、印章、纹理和图像工具。输入采样、缩放后的精度以及撤销数据结构都是可继续深入的主题。
3. **算法图案。** 使用重复、对称、噪声、扰动和规则生成变化。学习控制随机种子，让作品可复现；把参数分成结构、颜色和运动三类，便于理解和比较。
4. **文字图形化。** 研究沿路径排字、文字点阵、字符粒子和动态字形。实际产品中可保留语义文字层，再让视觉层承担特效，以兼顾表达和内容获取。
5. **交互数据图形。** 将数据映射为位置、长度、面积、颜色和形状，加入筛选、缩放和细节查看。需要理解映射尺度、图例与单位，避免图形变化让用户失去比较基准。
6. **声音驱动视觉。** 将音量、频谱或节拍特征映射到图形参数。应区分哪些映射是数据表达，哪些只是艺术选择。输入设备授权、音频播放与静音体验都应在原型中处理。
7. **输入与环境响应。** 探索指针位置、拖动速度、摄像头或其他传感器输入。先用模拟输入验证规则，再接入真实信号；明确输入缺失、波动和退出时的画面行为。
8. **交互叙事与游戏化图形。** 通过探索、选择、反馈和状态变化组织故事或练习。图形应表达规则，让用户理解自己能做什么。小游戏需要单独设计目标、失败、重试与结束。

### 7.3 练习与验收

完成一个“文字粒子画板”：输入文字后形成点阵，指针移动产生扰动，停止后恢复。允许修改粒子密度、恢复速度和颜色。记录固定种子的结果，检查窗口缩放、触摸操作、输入为空和长文本。对屏幕阅读器提供原始文字与操作说明。

参考入口：[p5.js](https://p5js.org/)、[D3](https://d3js.org/)。

## 08 三维内容与空间设计

### 8.1 研究对象与先修要求

三维作品由形体、表面、灯光、相机、动画和空间关系组成。基础知识包括三维坐标、向量、变换和透视。可以先在内容制作工具中理解场景，再使用 Three.js 等工具将模型与网页交互连接起来。

### 8.2 八个横向分支

1. **形体与建模。** 学习基础几何、拓扑、细分、雕刻和比例。产品、角色、建筑等类型有不同的结构要求。用于网页的模型还应考虑可见距离、细节的重要性和可承受资源量。
2. **UV 纹理与材质。** 研究二维图像怎样映射到表面，以及粗糙、金属、透明等属性怎样影响视觉。纹理分辨率应匹配实际观看尺度，色彩纹理与数据纹理的处理也需要区别。
3. **灯光与环境。** 设计主次光线、背景环境和明暗结构。通过灯光使形体可读，并传递材质特征。需要观察阴影、反射和环境贴图对视觉及性能的影响。
4. **相机与构图。** 学习透视、正交、焦距、视野和镜头运动。页面上的标题、按钮和模型应共同构图。移动端重新安排镜头与界面，通常比简单缩放桌面版本更有效。
5. **角色与物体动画。** 学习骨骼、关键帧、形变和动作混合。机械产品拆解与角色动作需要不同控制方式。要定义动画何时开始、怎样停止、用户输入如何接管。
6. **场景与环境设计。** 组织建筑、地形、植被、道具和路径，建立视觉引导与空间层级。大场景还需要分区加载和清楚导航，避免用户在空间中失去方向。
7. **三维交互。** 实现选取、旋转、缩放、拖动、注释和局部查看。操作应让用户知道选中了什么、改变了什么，以及如何恢复视角。重要信息应有清楚的二维界面配合。
8. **资源制作与交付。** 管理模型格式、纹理、压缩、动画和版本，建立资产检查流程。加载前后、资源失败和低性能模式需要完整设计。场景能在制作电脑运行，还要进一步验证目标设备。

### 8.3 练习与验收

制作一个三维产品展示页，包含模型旋转、三个观察角度、部件说明和恢复默认视角。给每个观察角度安排相机与文字布局。记录资源体积、首次可交互时机和设备表现，并提供模型未加载时可阅读的产品信息。

### 8.4 横向组合

三维产品展示可结合品牌与摄影知识；建筑场景可结合空间叙事与地图；教学模型可结合标注、切面和解释性图形；XR 原型则需要进一步研究空间输入和身体尺度。

参考入口：[Three.js 示例](https://threejs.org/examples/)。

## 09 技术美术与实时效果

### 9.1 研究对象与先修要求

技术美术负责让美术目标成为可控制、可维护、可运行的效果。需要对材质、灯光、动画、图形程序和资源流程都有基本理解。先完成一套稳定的三维场景或二维图形，再开发自定义效果，比较容易判断问题来自哪里。

### 9.2 八个横向分支

1. **着色器编程。** 学习顶点处理、片元颜色、纹理采样、插值和坐标空间。GLSL 常用于 WebGL；WGSL 是 WebGPU 的着色语言。框架还可能提供自己的节点或表达层，应理解其与底层程序的关系。
2. **程序化材质。** 使用噪声、函数和参数生成纹理或表面变化，形成金属、岩石、水面或抽象材质。需要控制尺度、重复规律和时间变化，确保材质适应不同模型与镜头距离。
3. **实时粒子与视觉特效。** 设计粒子的生成、生命、速度、颜色、尺寸和消亡。火花、能量线和文字粒子可以共享部分机制，但应分别设计形态与节奏。数量和透明叠加会影响成本。
4. **画面后处理。** 对已渲染图像进行辉光、景深、扭曲和色彩处理。了解每个处理步骤依赖哪些输入，以及怎样与透明、色彩空间和其他处理配合。效果应可单独启停和比较。
5. **风格化渲染。** 研究卡通、素描、水彩、版画等视觉表达，将规则映射到轮廓、阴影、纹理和色彩。风格化需要同时调整资产、灯光、构图和运动，才能形成一致作品。
6. **资产工具与制作流程。** 编写检查、批处理、导出和预览工具，帮助团队稳定生产内容。一个工具应说明输入约束、输出结果、失败原因和版本关系，减少重复劳动。
7. **效果参数与控制界面。** 为设计者提供有意义的参数，例如波幅、恢复速度和颗粒密度。参数范围要可解释，预设应可保存与比较。复杂效果需要明确哪些参数能安全实时修改。
8. **性能与质量分级。** 根据设备能力和目标场景调整粒子数、分辨率、阴影与后处理。先测量瓶颈，再选择优化或简化。记录视觉变化，确保低质量模式仍然传达关键内容。

### 9.3 练习与验收

制作一个“图片被指针推开后恢复”的效果，记录 UV 扰动、输入影响和恢复曲线。增加强度、范围、衰减控制，提供静态模式。检查触屏、窗口变化、连续操作、页面离开后的清理，并比较不同资源大小下的性能。

参考入口：[Three.js ShaderMaterial](https://threejs.org/docs/?q=ShaderMaterial)、[WebGPU API](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API)。

## 10 生成艺术与物理仿真

### 10.1 研究对象与先修要求

生成艺术通过规则和参数产生作品；物理仿真通过模型近似描述运动与相互作用。两者能够结合，也有不同评价重点。艺术规则可以服务于表达；物理模型若用于教学或分析，需要说明近似条件与有效范围。

### 10.2 八个横向分支

1. **随机与受控变化。** 使用随机种子、概率分布和噪声组织差异。随机种子用于复现一个结果，参数范围用于控制作品风格。可以制作系列海报、变化纹理和可生成的视觉身份。
2. **几何与图案生成。** 探索分形、铺砌、曲面、对称及其扰动。学习规则之间的组合，并观察局部变化怎样影响整体。作品应保留可理解的参数和生成过程。
3. **生长与扩散。** 用分枝、扩散、迭代规则和场生成植物或抽象形态。需要定义初始条件、边界、终止条件和资源限制。模拟自然外观时应说明采用了什么简化。
4. **群体与智能体。** 让个体根据邻居、目标和环境调整行为，形成鸟群、鱼群和人群等效果。可以研究局部规则与整体组织之间的关系；规模扩大后需要考虑邻域查询效率。
5. **粒子与力场。** 用位置、速度、加速度和外力更新系统。常见力包括吸引、排斥、弹簧和阻尼。选择合适时间步长并处理大间隔，避免运行速度变化导致结果失控。
6. **流体、布料与软体。** 根据目标选择模型，逐步学习数值积分、约束、碰撞和稳定性。视觉演示可以使用简化模型；工程或科学应用则需要验证精度。真实感与计算成本需要明确取舍。
7. **声音、数据与环境驱动。** 用输入数据控制生成过程，并设计映射、平滑和边界。输入缺失或突变时应有可解释的行为。作品应清楚区分实测数据、模拟数据与艺术性变换。
8. **生成系统的策展。** 比较多组结果、选择参数区域、建立系列和呈现方式。随机结果经过选择、编排和解释才能形成完整作品。保存种子、参数、版本和图像，有助于后续复现与改进。

### 10.3 练习与验收

完成一个可调的群体运动作品，提供个体数、邻域半径、聚集和分离强度等控制。用相同初始条件比较参数变化，记录每组结果和运行成本。用户应能暂停、恢复和重置，并理解每个参数大致改变什么。

参考展示：[Three.js 鸟群](https://threejs.org/examples/webgl_gpgpu_birds.html)、[Three.js 星系](https://threejs.org/examples/webgpu_tsl_galaxy.html)。这些展示用于观察方法与效果，实际运行表现取决于浏览器、设备和版本。

## 11 图形工程与渲染系统

### 11.1 研究对象与先修要求

图形工程处理场景怎样被计算、组织和绘制。先修知识包括向量矩阵、坐标变换、图形管线、资源管理和性能分析。学习可以从一个小型渲染模块开始，再逐步扩展场景规模与效果种类。

### 11.2 八个横向分支

1. **渲染流程与管线组织。** 理解几何、材质、相机和灯光怎样参与一次绘制，研究多个绘制阶段之间的资源依赖。合理组织流程有助于加入阴影、反射、后处理和调试视图。
2. **光照与阴影。** 深入直接照明、间接照明、环境光和阴影算法。比较不同方法的精度、噪声、内存和时间成本。镜头移动、物体运动和薄表面等情况应作为测试条件。
3. **材质与颜色管理。** 研究表面反射、透明、体积介质和色彩转换。理解线性空间与显示输出之间的关系，让纹理、灯光和后处理正确配合。视觉问题有时来自颜色流程而非参数大小。
4. **场景结构与可见性。** 管理场景层级、包围体、裁剪、实例化和细节层次。核心是让计算集中到当前画面需要的内容上，同时保持变化平滑，避免细节切换突兀。
5. **资源加载与内存。** 规划纹理、模型、缓冲区、压缩和缓存。研究按需加载、资源复用、释放与重新加载。长时间运行、频繁切换场景和设备资源不足时也需要可预期行为。
6. **GPU 并行计算。** 理解线程、工作组、数据布局、同步和带宽。选择适合并行的问题，例如粒子更新和图像处理。并行化需要考虑数据搬运与同步成本，并通过测量判断收益。
7. **性能剖析与平台适配。** 区分 CPU、GPU、网络和内存瓶颈；固定测试条件，记录帧时间和尖峰。WebGPU 等能力应依据目标平台检测，并设计合适的替代路径。
8. **引擎接口与调试工具。** 设计材质接口、场景接口、渲染配置、资源生命周期和诊断界面。自研系统的价值应对应一个明确需求，例如专门的二维编辑、科学体数据或大规模产品场景。

### 11.3 练习与验收

在同一场景中对比两种材质或阴影方案，固定相机、资源与设备，记录画面差异、帧时间和内存。建立调试视图，说明数据来自哪个阶段。结论应注明条件，避免把单个设备结果推广为所有平台表现。

### 11.4 实时与离线渲染的边界

实时展示要在交互节奏内持续更新；电影等离线制作可以为单帧投入更多计算。两者可以共享光照和材质原理，但质量目标、时间预算和生产流程不同。学习电影渲染器时，应明确哪些思想能够迁移到网页实时场景。

参考入口：[WebGPU API](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API)、[Disney Hyperion](https://www.disneyanimation.com/technology/hyperion/)。

## 12 图形学与视觉计算研究

### 12.1 研究对象与先修要求

这一方向关注现有方法的局限与改进，需要数学、程序实现、文献阅读和实验设计。建议从可复现的小问题入手，逐步理解数据、假设、算法、评价与适用条件之间的关系。能够清楚复现并解释一个方法，是有价值的阶段成果。

### 12.2 八个横向分支

1. **几何处理。** 研究网格重建、简化、修复、参数化和变形。需要同时观察形状误差、拓扑、法线和计算成本。实际应用包括模型处理、数字制造、动画和编辑工具。
2. **场景表示。** 比较网格、点、体积、隐式表示、辐射场和高斯表示怎样保存信息。不同表示在编辑、存储、渲染、重建和动态变化方面有不同特征，应根据任务选择。
3. **重建与新视角合成。** 从多视图图像等输入恢复场景或合成新的观察角度。关注相机估计、遮挡、稀疏输入和未观测区域。重建外观、恢复可编辑几何与获得物理材质是不同任务。
4. **逆向与可微渲染。** 使用图像和场景之间的关系估计材质、光照或形状。问题可能存在多种解释，需要约束、先验和合适数据。应明确优化哪些参数，哪些条件保持已知。
5. **图像生成与编辑。** 探索生成模型、可控编辑、风格和一致性。评价应包含内容正确性、可控性、重复性和任务适配。应用到设计时还需要保存来源、编辑记录和素材使用条件。
6. **高效模拟与计算。** 改进模拟速度、稳定性或精度，研究并行方法、近似与混合方案。每种简化应说明适用情况，视觉演示和科学分析需要各自的评价标准。
7. **感知质量与评价。** 结合图像误差、任务表现和人的评价比较方法。一个数值指标只能反映部分差异；主观实验应控制展示方式与顺序，并说明参与者和样本范围。
8. **复现与研究工具。** 管理代码、依赖、数据、随机种子、训练或运行配置。为每个实验保留可追踪记录。发现无法复现的部分时，应记录差异和可能原因，再设计验证。

### 12.3 研究项目的最小结构

一份完整的小型研究报告应说明问题、现有基线、输入数据、方法、评价、结果和限制。先证明基线能够在你的条件下运行，再改变一个因素。保存失败案例，帮助界定方法的边界。

### 12.4 练习与验收

选择一个公开图形算法或小型重建项目，按原始说明运行，固定数据和参数，至少记录一组成功与一组困难情况。说明复现了哪些结果、有哪些差异、可能由什么造成，并给出能够重跑的步骤。

参考项目：[3D Gaussian Splatting](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/)、[Mitsuba 3](https://www.mitsuba-renderer.org/)、[Mitsuba 可微渲染教程](https://mitsuba.readthedocs.io/en/stable/src/inverse_rendering/gradient_based_opt.html)。

## 13 计算设计、设计系统与创作工具

### 13.1 研究对象与先修要求

这一领域把设计规则变成可重复使用的系统。设计系统解决多页面、多团队的一致性；计算设计用参数和约束组织变化；创作工具让其他人直接操作这些规则。先理解真实制作过程，再决定哪些步骤适合抽象和自动化。

### 13.2 八个横向分支

1. **设计令牌。** 把色彩、字号、间距、圆角和运动等规则保存为有含义的变量。区分基础值与语义角色，支持主题和品牌变化。命名应帮助使用者选择正确用途，而不只描述一个颜色值。
2. **组件与模式库。** 维护组件状态、组合方式、内容约束和使用说明。模式库还应解释搜索、上传、筛选、编辑等完整任务。组件的可访问性和数据边界应进入验收标准。
3. **参数化设计。** 用参数控制形状、布局、字体和图案。选择有意义的控制量，明确范围和依赖。使用者应能预测改动方向，并保存与恢复方案。
4. **约束与自动布局。** 把最小尺寸、对齐、优先级、比例和内容适应转化为规则。遇到空间不足或约束冲突时，应有清楚处理。适合自动海报、文档、仪表盘和多尺寸模板。
5. **节点式编辑。** 用节点和连接表达数据、材质、动画或工作流。需要处理类型、连接有效性、执行顺序、错误定位和图规模。编辑器本身也需要缩放、选择、撤销和导航。
6. **直接操纵与所见即所得。** 允许用户在画面上拖动、调整和创建，并即时看到结果。需要建立稳定的数据模型，让视觉操作、属性面板和代码表示保持一致。
7. **版本、资产与协作。** 管理组件变更、设计资源、引用关系、迁移和多人编辑。协作工具应清楚表达他人的位置、操作与冲突，保存失败时要保护草稿。
8. **生成式辅助创作。** 用 AI 提供候选布局、素材或代码，再由用户比较、修改和接受。应能局部重做、撤销、追踪改动，并保留用户明确设置的约束。需要验证生成结果的真实可用性。

### 13.3 练习与验收

制作一个小型页面区块编辑器，允许调整标题、图片、配色和布局，提供三个预设，并支持导出配置。修改配置后应能恢复同一个结果。测试长文本、图片缺失、极端参数和撤销，观察规则是否稳定。

### 13.4 从个人规范到可用系统

先在真实项目中发现重复，再提炼组件与令牌；当多个场景存在相同规则时，再开发工具。记录每条规则解决什么问题，避免设计系统积累大量无人理解的参数。系统需要持续维护与使用反馈。

<a id="chapter-14"></a>
## 14 人机交互与新型媒介

### 14.1 研究对象与先修要求

HCI 研究人与计算系统如何协作。它联系计算机科学、设计、心理学和其他领域。网页原型可以成为研究载体，实体材料、声音和空间也可以进入交互。先明确要支持的活动，再决定使用何种输入与媒介。

### 14.2 八个横向分支

1. **输入方式。** 比较鼠标、触摸、笔、键盘、语音、手势和眼动等输入的特征。考虑精度、疲劳、环境和误触。新输入方式需要明确校准、反馈和替代操作。
2. **空间交互。** 研究三维选取、移动、旋转、导航和空间标注。需要考虑深度判断、遮挡、身体尺度与操作舒适度。空间原型应说明使用的设备和实际测试条件。
3. **实体与可触交互。** 将数字状态与真实物体、材料或形变联系起来。用户可通过摆放、触摸或操纵对象参与计算。设计需要同时考虑感知、机械约束、反馈和系统可靠性。
4. **多人协作。** 支持共同查看、讨论、编辑和决策。研究角色、权限、共享注意力、操作冲突和历史。协作质量与共同理解相关，需要观察多人真实任务。
5. **人机共创。** 设计人的目标、系统建议和持续修正之间的关系。让用户理解建议依据、影响范围和控制方式。接管、拒绝、撤销和恢复应成为完整交互的一部分。
6. **学习与解释工具。** 用可操作图形、模拟和反馈帮助人探索概念。需要确定学习目标、已有知识、操作与概念之间的映射，并评价是否促进理解。
7. **原型与研究方法。** 使用纸面、交互、技术和实体原型验证不同假设。选择访谈、观察、任务测试或实验时，应说明每种方法能回答什么问题，并尊重参与者的知情与退出选择。
8. **媒介与创作方式。** 探索人怎样使用动态画面、共享空间或物理材料表达思想。研究成果可以是工具、交互技术、设计原则或对使用行为的发现。

### 14.3 练习与验收

设计一个帮助理解复杂关系的交互原型，写出用户应学会或完成的具体任务。准备一种现有表达作为对照，观察用户怎样探索、哪里困惑、是否能迁移理解。报告应区分个人观察、初步发现与经过充分验证的结论。

参考入口：[ACM SIGCHI](https://sigchi.org/about/)、[Dynamic Pictures](https://worrydream.com/DynamicPicturesMotivation/)、[MIT inFORM](https://tangible.media.mit.edu/project/inform/)、[Dynamicland](https://dynamicland.org/)。后两个项目涉及屏幕以外的媒介，适合作为交互研究视野的拓展。

## 15 感知与认知研究

### 15.1 研究对象与先修要求

感知与认知研究帮助解释人怎样识别信息、分配注意、形成理解和完成动作。用于设计时，应把理论转化为可观察的问题，并通过原型验证。研究结论具有条件与边界，具体用户、任务和环境仍然重要。

### 15.2 八个横向分支

1. **视觉分组与组织。** 研究接近、相似、连续、边界和图底关系怎样影响结构识别。应用到界面时，可以比较间距、边框和背景分组各自是否帮助用户理解。
2. **注意与显著性。** 观察用户先看到什么、哪些变化会吸引注意，以及注意是否服务于任务。过多高强调元素可能相互竞争，因此需要安排主次并测试。
3. **记忆与外部表示。** 研究信息怎样被记住、比较和调用。界面可以保留上下文、历史和对照，减少用户在多个页面之间记忆内容的负担。
4. **理解与心智模型。** 用户会根据经验推测系统怎样工作。通过名称、结构和反馈帮助其建立合理理解，尤其要检查系统行为与用户预期不一致的位置。
5. **动作与时间知觉。** 研究操作距离、目标尺寸、反馈延迟和连续动作的体验。动效是否让人感觉系统响应、是否解释了对象变化，都可以通过具体任务观察。
6. **多感官关系。** 研究视觉、声音和触觉怎样配合表达状态或空间。各通道应有清楚分工，同时考虑环境和感官能力差异。关键内容可以通过多种形式获得。
7. **个体、文化与情境差异。** 经验、语言、能力、设备和使用环境会影响理解与判断。设计者应主动检查自己的默认假设，并邀请有代表性的使用者参与。
8. **测量与实验。** 使用任务成功、错误、耗时、回忆、主观评价等指标回答问题。眼动等设备数据只是证据的一部分，不能直接等同于理解或喜好。报告应说明方法和限制。

### 15.3 练习与验收

用同一份信息制作两个界面，只改变分组方式或层级表达。为参与者设置明确任务，记录操作过程与解释。控制内容、设备和任务差异，避免一次测试同时改动过多因素。

### 15.4 与设计实践的连接

把认知知识用于提出假设，例如“把说明放在输入位置附近可能更容易找到”，再通过测试观察。理论可以指导问题的选择，具体设计仍需面对实际使用证据。

<a id="chapter-16"></a>
## 16 美学、艺术指导与设计哲学

### 16.1 研究对象与先修要求

这一领域关注作品表达什么、为什么采用某种形式，以及各部分怎样形成整体。可以从观察和分析作品开始，学习设计史、艺术史、摄影、电影和视觉文化。实践中需要形成明确的设计命题，并通过具体页面检验。

### 16.2 八个横向分支

1. **形式与构图。** 研究比例、节奏、平衡、重复、对比和变化，观察这些选择如何影响阅读与感受。固定比例和网格是可以选择的工具，使用方式应由内容与表达目标决定。
2. **风格史与视觉文化。** 理解不同风格的历史背景、媒介条件和表达目的。迁移一种风格时，要识别它的核心组织逻辑，并检查它是否适合当前内容与用户。
3. **符号与意义。** 研究图形、颜色、材料和动作怎样承载意义。符号解释可能因文化和场景变化，重要信息应提供清楚语境，并通过用户反馈验证。
4. **叙事与情绪。** 安排信息出现的顺序、情绪变化、停留和转折。网页中的滚动、章节和交互可以成为叙事手段，但阅读者也需要选择和控制自己的节奏。
5. **艺术指导。** 统一字体、图像、颜色、材质、灯光、声音和运动。把抽象目标转化为能够执行的规则，例如镜头语言、图片裁切、素材主题和动画节奏。
6. **设计原则与价值取舍。** 明确产品重视效率、探索、可信、安静或其他目标，并据此处理冲突。原则应能够解释具体选择，例如为何减少步骤、为何保留某段说明。
7. **批评与评价。** 学会描述作品目标、形式、效果和限制，用具体证据提出修改。区分个人偏好与任务问题，让评审能够推动改进，并记录不同方案的取舍。
8. **原创语言与长期实践。** 通过系列作品逐步形成稳定的关注点、规则和表达方式。原创可以体现在问题选择、内容组织、视觉规则或交互机制。持续积累草图、失败实验和制作记录。

### 16.3 练习与验收

为一个主题建立两种艺术方向，各自写一页说明：希望传达什么、哪些形式选择支持它、哪些内容最重要。制作至少三个关联页面或场景，再请他人描述感受到的特征，比较其理解与设计意图。

### 16.4 与工程和研究的关系

艺术指导帮助确定值得实现的体验；工程让表达稳定运行；研究帮助理解效果和边界。高阶实践需要在这几种能力之间往返，把抽象判断落实到文字、操作、素材和系统行为。

<a id="chapter-17"></a>
## 17 十八个横向拓展方向

以下方向可以接入前面的多个领域。它们按实际问题组织，适合用来发现新的项目题材、补足产品能力或发展长期专长。

### 17.1 内容设计与信息编辑

内容设计负责标题、说明、按钮、错误提示、帮助与引导之间的一致性，也涉及信息出现的时机。学习如何把复杂概念拆成用户能够理解的内容单元，如何在有限空间保留必要条件，以及如何维护术语。

可做项目：重写一套注册、资料上传或课程选择流程，为每条文案说明使用场景。验收时观察用户是否知道要输入什么、为什么需要、结果会怎样。该方向连接视觉排版、UX 和国际化。

### 17.2 数据可视化与可视分析

从图表类型进一步扩展到数据语义、交互筛选、联动视图、异常解释和分析流程。关键是让图形支持真实问题，例如比较、定位、追踪和验证。需要学习尺度、聚合、缺失值和不确定性表达。

可做项目：一个包含筛选、趋势、分布和明细联动的数据工作台。验收时给用户设置分析任务，检查是否能够找到证据，并核对图形与原始数据一致。大数据专业背景可以在这一方向发挥作用。

### 17.3 地图与地理空间交互

地图设计涉及投影、比例尺、地理数据、图层、标注、聚合和空间筛选。不同缩放等级应提供不同细节，位置与范围应准确表达。地图适合处理空间关系，普通列表和图表可以承担精确比较与阅读。

可做项目：校园设施、公共服务或实验站点地图，支持区域筛选、对象详情和列表联动。验收应检查数据坐标、标注遮挡、触屏操作和定位失败状态，并记录数据来源。

### 17.4 科学可视化与交互解释

研究如何表达函数、向量、流场、体数据、时间演变和不确定性。核心要求是科学意义与视觉编码一致。模型输入、坐标、单位和假设需要清楚，颜色和动画也应支持理解。

可做项目：可调参数的数学或物理解释工具。先定义一个明确学习问题，再设计交互。通过数值核验与用户解释验证结果，区分真实计算、近似模型和仅用于示意的图形。

### 17.5 无障碍与包容性设计

横向关注视觉、听觉、运动、认知差异，以及临时和情境性限制。学习语义结构、键盘焦点、文字对比、字幕、表单提示、放大阅读和减少动态效果等。设计稿、代码和内容都参与这一工作。

可做项目：为已有页面完成一轮无障碍改进。结合自动检查、键盘操作和适当辅助技术测试，保存具体问题与修正证据。自动工具覆盖有限，人工任务检查仍然重要。参考：[W3C WAI](https://www.w3.org/WAI/fundamentals/accessibility-intro/)。

### 17.6 国际化与跨文化设计

研究多语言文本扩展、日期数字格式、阅读方向、字体、搜索和符号含义。组件需要适应长短不同的翻译，内容与语言资源也需要可维护结构。文化适配要依据具体对象，避免凭印象给群体贴标签。

可做项目：为一个工作台增加第二种语言，检查长文本、日期、排序、空状态和错误提示。页面结构与文本含义都需要审查。参考：[W3C Internationalization](https://www.w3.org/International/)。

### 17.7 声音设计与声学交互

扩展到提示音、环境音、音频层级、语音播放与视觉节奏。声音应有可识别含义，并允许控制音量和静音。公共环境、耳机和设备扬声器会影响体验，需要在实际使用条件下比较。

可做项目：带可选声音反馈的计时、学习或创作工具。为每种声音定义触发和作用，检查同时触发时是否混乱。关掉声音后，状态与结果应通过其他方式表达。

### 17.8 触觉与身体交互

关注振动、力反馈、动作范围、姿态与触摸材料。技术依赖设备能力，可先用简单硬件或可用设备验证。反馈应能区分状态，并考虑疲劳、可达范围和个体差异。

可做项目：研究一个触摸或笔输入任务，比较不同反馈方式对操作的影响。记录硬件与测试条件，控制可复现性。网页与实体装置可能承担不同部分，应明确系统边界。

### 17.9 AI 产品与生成式界面交互

AI 界面需要处理流式输出、等待、取消、重新生成、局部编辑、来源展示和不确定结果。设计者应让用户理解当前状态、哪些内容已经确定、如何纠正系统，以及哪些动作会产生实际影响。

可做项目：一个资料分析或创作助手，提供任务进度、可编辑结果、来源查看、版本比较与恢复。重要成果应能够导出与独立保存。参考：[Microsoft HAX Toolkit](https://www.microsoft.com/en-us/haxtoolkit/)，用于理解人机协作设计问题。

### 17.10 协作编辑器与专业工作台

横向进入多人光标、选区、评论、历史、权限、冲突和离线恢复。专业工具还需要快捷键、命令搜索、批量操作、面板布局和工作区保存。复杂交互应建立明确的数据与状态模型。

可做项目：一个带撤销、评论和版本恢复的画布或文档编辑器。先把单人编辑做完整，再加入多人协作。验收重点是内容一致性、操作可解释性和异常情况下的数据保护。

### 17.11 服务设计与全流程体验

把界面放进更大的服务过程，观察线上、线下、通知、人工处理和结果交付之间的关系。学习用户旅程、服务触点、前台与后台流程。设计需要明确各方责任和状态传递。

可做项目：校园预约、报修或活动报名服务，梳理发起、受理、处理、反馈和关闭。界面应反映真实流程，明确用户何时需要等待、何时可以行动、发生问题联系谁。

### 17.12 游戏体验与交互叙事

学习规则、目标、反馈、难度、节奏和叙事选择。游戏化界面应围绕用户任务设计，奖励和挑战需要能够解释其作用。交互故事还涉及分支、回溯、进度和结局。

可做项目：一个可完成的小型知识游戏或互动故事。定义清楚的开始、核心循环、失败与重试、结束。观察用户是否理解规则，避免只评价画面而忽略实际可玩性。

### 17.13 空间计算与数字展览

把三维、空间导航、声音、多人体验和实体环境结合起来。可以研究展品距离、视线引导、字幕、导览和空间标注。空间体验应在适合的设备或场景中测试，尤其关注方向感与舒适度。

可做项目：一个小型虚拟展览，限定展品数量，设计路线、自由探索、详情查看和退出。将空间布局与展览叙事共同评审，并提供清楚的替代阅读入口。

### 17.14 设计运营与资产治理

研究团队怎样维护组件、令牌、模板、图标、素材与使用说明。建立命名、状态、负责人、变更记录和淘汰机制。设计系统的价值需要通过真实项目采用和问题反馈体现。

可做项目：为已有产品建立组件与资产目录，识别重复、缺失和不一致，选择一批高频组件统一。验收时让其他人独立使用，并记录理解成本与修改需求。

### 17.15 视觉质量自动检查

把截图比较、内容边界、主题、视口、字体加载和组件状态纳入检查。自动化适合发现回归，人工评审负责理解变化是否合理。为动态内容、时间和随机结果建立可复现条件。

可做项目：给一套组件建立固定数据的展示页，在不同主题与宽度下生成检查结果。对每个差异说明是预期修改还是问题，并避免用测试覆盖率代替视觉判断。

### 17.16 感知性能与适应性呈现

研究用户怎样体验等待、渐进加载和交互响应。把内容优先级、资源加载、骨架、进度和局部更新结合起来。性能改进应通过实际测量与任务观察判断。

Core Web Vitals 提供了一组常用的外部参照：按真实访问的第 75 百分位评估，LCP（最大内容绘制）不超过 2.5 秒、INP（交互到下一次绘制）不超过 200 毫秒、CLS（累积布局偏移）不超过 0.1 被视为良好。这些阈值适合发现加载、响应和布局稳定性问题，但不能代替对关键任务的观察；三维、编辑器等长时间运行的页面还需要单独记录帧时间与内存。参考：[web.dev 阈值说明](https://web.dev/articles/defining-core-web-vitals-thresholds)。

可做项目：改进一个图片多或三维资源大的页面，分别观察首次内容、可操作时机、关键任务完成和持续运行情况。简化模式应仍然能够完成主要任务，避免只有空白或错误提示。

### 17.17 信任、权限与可恢复设计

界面需要清楚表达权限、数据用途、操作范围和结果。高影响操作应让用户理解变化，提供合适的预览、确认或撤销。错误恢复、历史和来源说明也会影响信任。

可做项目：设计文件分享、批量修改或自动化任务的完整流程。检查用户能否判断谁能访问、哪些对象会改变、怎样停止和恢复。授权信息应和实际系统行为保持一致。

### 17.18 数字制造与实体计算

将程序化几何、图形或交互输出到实体材料和设备，例如激光切割图案、可组合模块或感应装置。需要学习尺寸、材料、制造约束、设备接口和校准。实体结果通常要求比屏幕更明确的单位与公差。

可做项目：制作一套可参数化生成的实体模块或纸面原型，记录参数到成品的过程。使用设备时遵循其操作规范，先进行小规模验证，再扩大制作范围。

### 18.2 典型组合路线

| 目标作品 | 共同基础 | 特色分支 | 首要验收问题 |
| --- | --- | --- | --- |
| 精致的 SaaS 或管理系统 | 前端、UX、视觉 | 设计系统、微动效、数据表 | 用户能否高效完成完整任务 |
| 品牌官网 | 前端、视觉、内容 | 艺术指导、动态排版、滚动叙事 | 品牌与核心信息是否清楚 |
| 三维产品发布页 | 视觉、三维、交互 | 灯光、材质、镜头、技术美术 | 模型表现与页面操作是否协调 |
| 可视分析工作台 | 前端、数据设计、UX | D3、交互图表、科学计算 | 图形是否准确支持分析 |
| 互动教学工具 | 信息设计、交互 | 二维图形、认知研究、模拟 | 操作是否帮助理解概念 |
| 生成艺术 | 创意编程、艺术指导 | 噪声、粒子、仿真、着色器 | 规则是否形成可控表达 |
| 虚拟展览 | 空间、视觉、交互 | 声音、镜头、导览、XR | 探索与内容理解是否成立 |
| 专业编辑器 | 前端、复杂交互 | 计算设计、图形系统、协作 | 创建、编辑、恢复是否完整 |
| 研究原型 | 编程、研究方法 | 图形算法或 HCI 技术 | 结果是否可复现并支持结论 |
| 实体互动装置 | 交互、艺术方向 | 传感器、材料、声音、形变 | 反馈是否可感知并稳定运行 |

### 18.3 同一效果可以有多种实现

例如水波可以由 CSS 与图片形成近似装饰，可以由着色器产生视觉扭曲，也可以用模拟计算更新水面状态。应根据交互需求、真实感、控制能力和设备成本选择方法。描述作品时说明采用了哪种方式，有助于理解其能力边界。

同样，“玻璃效果”可能指背景模糊与透明叠层，也可能指三维透射材质或光线追踪中的折射。这些表现与计算过程不同，选型前应先用参考图和交互说明明确目标。

### 18.4 三种横向扩展方法

**按表达媒介拓展：** 从文字到图形、图像、动画、声音、三维、实体。每增加一种媒介，都要说明它帮助用户理解或感受什么。

**按任务场景拓展：** 从阅读到搜索、比较、编辑、分析、探索、学习与协作。同一套视觉能力可以服务不同场景，但操作与评价方法需要调整。

**按专业职责拓展：** 从制作单个页面到制定规范、开发工具、组织资产、评审作品和开展研究。职责扩大后，沟通、文档和验证会成为核心能力。

## 19 常见视觉效果的实现拆解

下表提供实现思路。具体库与技术只是候选，应根据框架、目标设备和内容需求选择。

| 效果或体验 | 主要知识 | 实现思路 | 应重点检查 |
| --- | --- | --- | --- |
| 精致静态页面 | 版式、字体、色彩 | HTML、CSS 网格与视觉规范 | 内容层级与不同屏幕 |
| 杂志式排版 | 编辑设计、图片编排 | Grid、字体比例、图文关系 | 阅读顺序与长内容 |
| Bento 卡片布局 | 分组与网格 | Grid 区域安排与自适应 | 卡片优先级与内容变化 |
| 瀑布流 | 列布局、内容尺寸 | 选用适配目标平台的布局方案 | 阅读顺序与加载位移 |
| 渐变文字 | 背景与遮罩 | CSS 背景裁切等 | 对比与静态回退 |
| 磨砂玻璃界面 | 透明、模糊、分层 | CSS 半透明与背景滤镜 | 背后内容变化与绘制成本 |
| 鼠标聚光灯 | 坐标、事件、渐变 | 指针映射到局部渐变位置 | 触屏替代与事件频率 |
| 立体倾斜卡片 | 透视与变换 | 指针位置映射旋转角度 | 文字稳定与减少动态效果 |
| 按钮弹性反馈 | 动效、状态 | CSS 或动画库 | 连点、取消和真实结果 |
| 卡片展开详情 | 共享元素与布局 | 动画库或适用的浏览器能力 | 中断、返回和焦点 |
| 平滑列表重排 | 布局动画 | 记录前后位置并过渡 | 排序数据与视觉对应 |
| 拖拽吸附 | 命中、几何、状态 | 指针事件与吸附规则 | 撤销、键盘替代与边界 |
| 滚动叙事 | 时间线、内容编排 | 滚动进度关联场景状态 | 导航、节奏与手机端 |
| 动态文字 | 排版、遮罩、路径 | DOM、SVG 或图形层 | 语义文本与可读性 |
| 图片液态扭曲 | UV、噪声、输入 | 着色器采样偏移 | 资源比例与性能 |
| 粒子聚合成文字 | 点采样、力场 | Canvas 或 GPU 更新 | 数量与恢复稳定性 |
| 鼠标闪电 | 路径、随机、生命期 | 折线分叉与亮度衰减 | 闪烁强度与可关闭 |
| 音乐可视化 | 音频特征、映射 | Web Audio 与图形绘制 | 授权、静音与输入缺失 |
| 交互图表联动 | 数据映射、状态 | 图表与筛选共享选择状态 | 单位与数据一致性 |
| 三维产品旋转 | 模型、相机、材质 | 三维场景与旋转控制 | 加载、操作提示与恢复视角 |
| 产品拆解演示 | 物体层级、动画 | 部件变换与时间线 | 说明与部件关系 |
| 透明玻璃材质 | 透射、光照、环境 | 三维材质与相关渲染流程 | 背景、透明排序与成本 |
| 群体运动 | 邻域、速度、规则 | 智能体更新（CPU 或 GPU） | 参数稳定与邻域查询 |
| 流体与烟雾 | 数值模型、渲染 | 选择近似或物理模拟方案 | 模型假设与时间步长 |
| 照片场景浏览 | 重建、场景表示 | 使用适合数据的重建与渲染流程 | 未观测区域与资源成本 |
| 自动布局编辑器 | 约束、状态、数据模型 | 参数与约束求解加编辑界面 | 冲突、长文本与导出 |
| 生成式 AI 工作台 | 异步任务、人机协作 | 流式输出、版本、编辑与来源 | 取消、纠错与内容保存 |
| 实体形变界面 | 传感、控制、实体结构 | 硬件与软件共同设计 | 校准、可靠性与操作条件 |

### 19.1 一个完整拆解示例

目标是“用户滚动时，产品从完整外观逐步拆解，并出现部件说明”。先准备可分离部件的模型，再确定每个章节的相机、部件位置和说明。将滚动进度映射到一个确定的场景状态，使向上和向下滚动都能得到一致结果。

界面层提供章节导航、简化浏览和产品文字信息。资源未就绪时先展示可阅读内容；三维资源失败时保留说明。验收应包含快速滚动、窗口变化、触屏、减少动态效果偏好、跳转章节与资源加载失败。

### 19.2 从效果库学习的方法

先观察效果解决了什么表达任务，再看输入、状态、更新与绘制。用最小例子复现核心机制，替换成自己的内容，然后加入异常处理和适配。保存来源与依赖信息，并核对素材和代码的使用条件。

## 20 数学、编程与研究基础

### 20.1 按实际需要补充数学

| 知识 | 主要用途 | 适合开始学习的时机 |
| --- | --- | --- |
| 比例、坐标与单位 | 布局、映射、尺寸与位置 | 界面与二维图形阶段 |
| 三角函数 | 旋转、周期、波形、圆周运动 | 动态图形与三维阶段 |
| 向量与矩阵 | 方向、距离、变换、相机 | 三维与着色器阶段 |
| 插值与曲线 | 缓动、路径、参数过渡 | 动效阶段 |
| 概率与随机 | 变化、分布、噪声、采样 | 生成图形阶段 |
| 微积分基础 | 变化率、优化、运动模型 | 仿真与研究阶段 |
| 数值方法 | 时间步进、约束求解、稳定性 | 复杂仿真阶段 |
| 统计与实验设计 | 比较方案、研究证据 | 用户研究与算法评价阶段 |
| 图论与几何算法 | 连线、布局、路径、空间关系 | 编辑器、地图与图形工程阶段 |
| 优化方法 | 参数估计、自动布局、逆向渲染 | 计算设计与研究阶段 |

每学一个概念都应配一个可视化练习。例如学习向量后实现跟随与反弹；学习插值后比较不同运动曲线；学习随机分布后观察粒子分布差异。数学记录中写出输入、单位、输出和假设，帮助以后迁移。

### 20.2 编程基础的横向展开

**数据模型**决定界面能够保存和恢复什么。一个编辑器应明确文档、节点、选区、视图和历史分别怎样表示。先处理数据关系，再设计交互状态，可以减少后期冲突。

**算法与数据结构**影响规模增长后的表现。列表、树、图、空间索引和缓存各有使用场景。选择结构时依据访问与更新模式，并用实际数据观察成本。

**异步与生命周期**贯穿网络、资源、动画和设备。需要理解取消、清理、重复请求、过期结果和组件销毁。交互状态应能解释这些过程，而不是把异步细节暴露为用户困惑。

**软件结构**帮助作品持续修改。根据实际重复提炼模块，建立清楚接口，保存配置和依赖。把实验代码转为可交付组件时，应补齐输入约束、异常处理、文档和必要检查。

### 20.3 设计基础的横向展开

训练观察、比较、解释与修改。观察时描述客观特征；比较时尽量固定内容；解释时把形式与任务联系起来；修改时明确假设。建议保留参考分析、草图、失败方案和最终取舍，而不是只保存最后一张图。

### 20.4 研究基础的横向展开

学习提出范围明确的问题、寻找相关方法、选择基线、控制变量和报告限制。用户研究与算法研究都需要证据，但数据类型和方法不同。把“个人觉得更好看”“任务表现改善”“统计上支持差异”分别表达，避免混为一个结论。

### 20.5 每个分支都能形成的六种成果

1. 一个准确复现原理的最小示例。
2. 一个能够说明取舍的独立方案。
3. 一个处理真实内容和异常情况的项目。
4. 一组可重复使用的规则与组件。
5. 一份有证据的比较或评价报告。
6. 一个让他人能够使用的方法、工具或研究结果。

这些成果可以循环出现。深入后回到一个小组件，往往能够发现新的问题。

## 21 按目标选择学习路线

下面的路线以成果作为推进标准。实际学习速度取决于已有基础、投入时间与项目范围，可以在每个阶段停留并横向探索。

### 21.1 共同主干

先完成一个包含首页、列表、详情和表单的响应式项目，建立颜色、字体、间距与组件规则，补齐加载、错误、空状态和键盘操作。再为一个完整流程设计动效。通过这组成果，判断自己最需要补的是视觉、交互、实现还是工程质量。

### 21.2 路线 A 精致产品与业务系统

第一段学习前端布局、视觉层级和状态设计，成果是完整的多页面产品。第二段学习信息架构、复杂表单、列表和用户测试，成果是能够完成真实任务的工作台。第三段学习设计系统、主题、国际化和质量检查，成果是可扩展的组件与规范。

横向优先选择内容设计、无障碍、数据表和设计运营。阶段验收看任务是否完整、组件是否一致、真实数据是否适配，以及后续新增页面是否容易保持品质。

### 21.3 路线 B 品牌官网与创意前端

先完成视觉与品牌练习，再学习动态排版、SVG、Canvas 和时间线，最后选择必要的三维或着色器。建立一个具有清楚内容与视觉主题的官网，而后逐步加强交互表达。

横向可以进入摄影、插画、声音、编辑设计和叙事。验收看核心信息是否清楚、节奏是否合适、移动端是否成立，并检查复杂效果对加载和阅读的影响。

### 21.4 路线 C 数据与科学可视化

先学习数据类型、图形编码和交互筛选，再实现联动图表、地图或科学图形。之后深入不确定性、性能、大数据量和分析任务设计。把计算正确性与视觉表达放在同一验收流程中。

横向可以进入统计、地图、信息设计、认知研究和领域知识。成果应提供数据来源、单位、计算说明与可重复的分析案例。这条路线适合把数据科学能力与前端表达结合起来。

### 21.5 路线 D 三维与技术美术

先掌握场景、材质、灯光和相机，完成小型产品展示。随后学习着色器、噪声、粒子与后处理，并建立参数控制。再根据需要补充物理模拟、程序化资产与性能工程。

横向可以进入建模、摄影灯光、动画、声音和风格化美术。每个阶段都应交付可运行场景与性能记录，说明资产来源、设备条件和质量分级。

### 21.6 路线 E 图形研究与引擎研发

先建立数学、渲染与实验基础，再复现一个范围明确的公开方法。通过基线和对照理解瓶颈，然后选择几何、光照、场景表示、逆向渲染或高效计算深入。

横向可以进入数值分析、并行计算、机器学习和感知评价。成果应包含可复现代码、配置、数据说明、比较和失败案例。研究型训练通常需要长期积累，应持续缩小问题并形成阶段结果。

### 21.7 路线 F HCI 创作工具与原创媒介

从一个真实创作或协作任务出发，学习原型、用户研究和交互设计，再结合图形、AI、声音、空间或实体材料。制作工具原型，观察实际使用，逐步形成新的交互机制或设计原则。

横向可以进入认知、服务设计、艺术指导和媒介研究。验收看问题是否真实、原型是否可用、研究是否支持结论，以及使用者是否能理解并控制系统。

### 21.8 怎样安排每次练习

每次练习先选一个具体问题，例如列表重排、中文标题断行或材质光泽。写出预期结果，制作最小示例，再把它放进真实页面。最后记录变化、问题和下一次需要验证的事项。学习资料应当为当前问题服务，避免长期只收集链接。

## 22 十二个递进实战项目

### 项目 01 响应式个人作品页

**目标与范围：** 用真实项目内容制作首页、项目列表和详情，完成导航、联系方式与移动端布局。内容中加入长标题、不同图片比例和缺失信息，检查结构适应性。

**能力组合：** 前端界面、排版、图像与基础交互。先完成语义结构，再建立间距、字体和颜色规则。

**交付与验收：** 可运行页面、简短视觉规范和内容边界记录。使用不同宽度、放大文字、键盘和慢速资源条件检查，确保关键内容可读可达。

### 项目 02 同一内容的三种视觉方向

**目标与范围：** 为同一个产品制作简约、编辑设计和科技三种方向，每种包含首页片段、详情和空状态。固定内容，重点改变视觉组织。

**能力组合：** 版式、字体、色彩、图像和艺术方向。解释每种风格适合的用户与内容，而后选择一个方向继续完善。

**交付与验收：** 方向板、三个页面组和取舍说明。比较层级、可读性、一致性和实际内容适配，记录评审意见。

### 项目 03 完整资料上传流程

**目标与范围：** 实现文件选择、校验、上传、分析中、结果查看、失败重试和取消。可以使用明确标注的模拟数据验证流程。

**能力组合：** UX、内容设计、组件、异步状态与反馈动效。

**交付与验收：** 状态表、交互原型和可运行流程。测试重复提交、断网、超长文件名、取消后返回、空结果与错误恢复。检查用户能否判断任务进行到哪里。

### 项目 04 产品设计系统

**目标与范围：** 从已有页面提取颜色、字体、间距和至少一组高频组件，提供默认、悬浮、焦点、禁用、加载和错误等适用状态。

**能力组合：** UI、组件工程、无障碍、文档和资产治理。

**交付与验收：** 令牌、组件展示、使用规则和一个实际采用页面。让其他人按文档完成新页面，记录难以理解和无法覆盖的场景。

### 项目 05 连贯的动效流程

**目标与范围：** 为列表进入详情、编辑、保存和返回设计连续过渡。定义每个动画的触发、目标、持续、取消和恢复。

**能力组合：** 动效、状态机、布局与手势。

**交付与验收：** 动效说明、可操作项目和录屏。测试快速切换、中途反向、内容变化、触屏和减少动态效果模式，确保视觉与真实状态一致。

### 项目 06 可探索的数据工作台

**目标与范围：** 使用一份来源清楚的数据，提供概览、筛选、趋势、分布和明细联动，支持重置选择与查看数据说明。

**能力组合：** 数据处理、信息设计、图形、交互和前端状态。

**交付与验收：** 数据字典、图表说明、分析任务与项目。核对计算、单位、缺失值和图形映射，让用户根据图表回答具体问题。

### 项目 07 生成式图形海报

**目标与范围：** 使用固定种子和可调参数生成一组海报，支持颜色、结构密度与标题内容变化，并导出结果。

**能力组合：** 创意编程、排版、生成规则与艺术指导。

**交付与验收：** 参数说明、系列作品和生成工具。相同配置应得到可复现结果；长标题和极端参数应仍有可理解输出。

### 项目 08 三维产品展示

**目标与范围：** 制作一个产品场景，包含旋转、视角选择、部件标注和恢复默认。根据屏幕重新安排镜头与文字。

**能力组合：** 三维、灯光、材质、UI 与资源工程。

**交付与验收：** 场景、资产清单、加载与性能记录。测试资源失败、低性能设备、触摸操作和模型未就绪时的阅读路径。

### 项目 09 可控的实时特效

**目标与范围：** 选择液态图像、粒子文字或溶解其中一种效果，拆成输入、更新和绘制，提供少量有意义的参数与预设。

**能力组合：** 着色器或 Canvas、数学、动效、技术美术。

**交付与验收：** 最小原理演示、完整效果、参数说明和性能对比。检查暂停、重置、缩放、输入缺失和静态替代。

### 项目 10 可编辑的能力画布

**目标与范围：** 在画布上组织目标、知识、技能与任务，支持节点编辑、关系连接、缩放、搜索、撤销和保存。节点方向、层级和连线含义应可配置并保持清楚。

**能力组合：** 复杂交互、图形、数据模型、信息架构和创作工具。

**交付与验收：** 数据结构、交互规则、示例画布与可运行项目。测试大图、循环关系、断开的节点、长文本、误删恢复和刷新后恢复。后续可加入学习计划、能力验证与版本记录。

### 项目 11 AI 资料与职业探索工作台

**目标与范围：** 以一个对话工作区组织资料选择、任务发起、生成进度、可编辑结果和版本比较。可以选择资料分析、模拟面试或岗位能力匹配中的一个完整任务作为第一版。

**能力组合：** AI 交互、UX、内容设计、异步状态、设计系统。

**交付与验收：** 任务说明、来源展示、取消与纠错、结果保存和导出。区分用户资料、模型建议和待验证内容。职业规划场景围绕能力、学习与行动安排组织信息。

### 项目 12 研究复现或新媒介原型

**目标与范围：** 二选一开展。研究方向选择一个公开图形方法复现；交互方向选择一个真实活动制作新的表达或操作原型。限制问题规模，确保能够完整验证。

**能力组合：** 研究方法，加图形、HCI 或计算设计中的一个专长。

**交付与验收：** 问题、基线、方法、配置、结果、失败情况与限制。公开方法复现应注明来源；新交互应展示使用过程，并说明证据支持到什么程度。

### 项目记录建议

每个项目保存需求、参考、草图、规则、实现、验证和修改记录。作品集应展示关键问题与解决过程，并提供可运行成果。对于模拟功能、示意数据和研究局限，应在适当位置明确说明。

## 23 专业工作流程与 AI 协作

### 23.1 从目标到交付的工作流程

**第一步：明确任务与内容。** 写出用户是谁、在什么情况下使用、需要完成什么，以及成功的结果。准备真实或明确标注的示例内容，列出必要状态和限制。

**第二步：调研与参考分析。** 收集少量相关作品，分析其布局、字体、图像、流程和动效。为每个参考写明采用什么思路，核对素材与代码使用条件。

**第三步：组织信息与流程。** 建立页面清单、内容层级、任务路径和状态表。复杂流程先用低成本原型验证，避免在结构尚未明确时大量制作视觉细节。

**第四步：确定视觉方向。** 通过多个小范围方案比较风格，把选定方向转化为字体、颜色、间距、图片和动效规则。先用关键页面验证规则是否适用。

**第五步：设计组件与状态。** 提炼真实需要的组件，记录内容约束、属性和状态。补充加载、空数据、失败、权限、长内容和移动端。

**第六步：实现与连续检查。** 按完整流程逐步实现，边做边检查真实内容。把动效、资源和数据行为连接起来，并及时处理焦点、取消和异常恢复。

**第七步：验证与评审。** 检查视觉一致性、任务可用性、性能和可访问性。邀请适当用户完成任务，记录事实与解释，按影响和成本安排修正。

**第八步：交付与维护。** 保存设计规则、资产来源、依赖、使用说明和已知限制。上线后根据真实使用反馈继续改进，并维护版本与迁移说明。

### 23.2 一套可用于起步的视觉规则

以下数值用于构建初版基线，应根据内容、字体、阅读距离和设备调整。其中对比度和点击目标三行引自 WCAG 2.2 的 AA 级成功准则，属于可访问性底线，不宜随意放宽；具体条款与例外见 [WCAG 2.2 快速参考](https://www.w3.org/WAI/WCAG22/quickref/)。

| 项目 | 起步示例 | 调整依据 |
| --- | --- | --- |
| 间距 | 以 4 或 8 像素为基础，常用 8、16、24、32 | 分组关系、内容密度与触摸操作 |
| 字体层级 | 正文约 16 像素，小标题约 20 至 24，页面标题约 32 至 40 | 字体实际字面、页面用途与响应式 |
| 行高 | 正文先尝试约 1.5 至 1.8 倍 | 语言、行长与阅读任务 |
| 色彩角色 | 背景、内容、边界、主操作、成功、警示、错误 | 对比、语义与主题 |
| 文字对比 | 正文与背景至少 4.5:1；大字号文字（约 24 像素常规字重或 18.7 像素粗体以上）至少 3:1 | WCAG 2.2 AA 的 1.4.3；背景图片与主题切换时重新检查 |
| 非文字对比 | 图标、输入框边界、焦点指示等识别所需的图形至少 3:1 | WCAG 2.2 AA 的 1.4.11；状态不能只靠颜色区分 |
| 点击目标 | 一般不小于 24×24 CSS 像素，或与相邻目标保持足够间距 | WCAG 2.2 AA 的 2.5.8；触屏主要操作通常留出更大区域 |
| 圆角 | 为小控件、卡片、弹窗建立少量规则 | 品牌形态与层级 |
| 阴影 | 按悬浮层级建立少量预设 | 背景、叠层和设备效果 |
| 动效 | 小反馈可先在约 150 至 300 毫秒范围试验 | 距离、输入方式与理解需求 |
| 图像 | 约定比例、主体位置和缺失状态 | 内容题材与屏幕裁切 |

用真实内容检查规则之间的关系。例如字号增大后，行长和布局密度可能需要一起调整；图片变化后，对比和文字位置也可能需要重新安排。视觉规则应允许合理例外，并记录例外的原因。

### 23.3 AI 适合参与的环节

AI 可以帮助整理需求、分析参考、生成候选布局、制作草图、编写组件、补充状态清单、解释图形算法和检查代码。使用时应明确任务、约束和验收条件，并保留可比较的版本。

对于视觉任务，可以先让 AI 描述参考中的层级、间距、字体和素材，再要求提出几个方向。对于实现任务，提供框架、已有组件、数据模型和目标设备。对于复杂效果，先生成最小原理示例，再放入产品场景。

### 23.4 一份可以复用的设计任务说明

```text
产品与任务：说明用户在这个页面要完成什么。
内容：提供真实标题、正文、数据、图片与必要状态。
目标风格：描述希望形成的特征，并提供参考及具体借鉴点。
结构要求：说明导航、主内容、次要信息和主要操作。
视觉规则：给出字体、颜色角色、间距、圆角与素材方向。
交互要求：列出触发、状态、反馈、取消、恢复和键盘操作。
设备要求：说明桌面、手机、输入方式与性能条件。
技术环境：提供框架、组件库、已有接口及允许使用的资源。
交付内容：要求实现文件、状态说明和运行方式。
验收条件：列出具体任务、边界内容和需要比较的截图。
```

### 23.5 让修改反馈可执行

把“看起来不够精致”转化为具体观察，例如标题和正文层级不明显、卡片间距与分组关系不一致、图片裁切损失主体、按钮状态缺失。每次集中修改少量相关问题，再比较结果。复杂修改应注明需要保留的内容和已有行为。

可以要求 AI 给出不同方案及其适用条件，也可以让它先审查现有实现。最终仍需通过运行和使用验证，因为生成结果可能存在错误、缺失状态或与设计目标不一致的部分。

### 23.6 建立可复用的个人资产

建议保留五类材料：参考分析、视觉规则、可运行组件、效果原理实验和项目复盘。每份材料记录目的、输入、输出、限制和来源。这样积累的内容可以持续支持新的作品，而不是每次重新从零组织。

## 24 质量验收与问题诊断

### 24.1 视觉与内容检查

- [ ] 页面主任务和主要操作容易辨认。
- [ ] 标题、正文、注释和数值具有清楚层级。
- [ ] 分组、对齐、间距与内容关系一致。
- [ ] 颜色角色、图标风格和图片处理协调。
- [ ] 长标题、长数字、空内容和缺失图片能够正常呈现。
- [ ] 深浅主题或不同背景下保持可读性。
- [ ] 文案明确、术语一致，必要说明出现在合适位置。
- [ ] 页面实际内容与所需的视觉风格相匹配。

### 24.2 交互与流程检查

- [ ] 从入口到结果的主要任务完整。
- [ ] 加载、成功、失败、取消、重试和返回都有定义。
- [ ] 重复点击、快速切换和中途退出不会造成混乱。
- [ ] 编辑内容能够按设计保存、恢复或撤销。
- [ ] 选中对象、操作范围和结果清楚可见。
- [ ] 触摸、鼠标和键盘的关键路径可用。
- [ ] 弹窗和浮层的焦点、关闭与返回位置合理。
- [ ] 多步骤任务在中断后能够解释当前进度。

### 24.3 工程与可访问性检查

- [ ] 在目标宽度和文字放大条件下无关键内容遮挡。
- [ ] 资源加载失败时仍有有意义的内容或恢复路径。
- [ ] 核心操作无明显阻塞，记录了实际性能条件。
- [ ] 动画、事件、资源和异步任务能够合理清理。
- [ ] 表单标签、控件语义和焦点顺序清楚。
- [ ] 关键信息有适当的文字替代或其他表达。
- [ ] 用户减少动态效果或静音时能够完成主要任务。
- [ ] 设备不支持某项能力时有合适处理。

### 24.4 研究与原创项目检查

- [ ] 问题和目标明确，已有方法与来源可追踪。
- [ ] 输入、数据、参数与运行配置有记录。
- [ ] 比较方案使用尽量一致的条件。
- [ ] 结果包含失败情况与适用边界。
- [ ] 结论与证据范围一致，区分观察和推断。
- [ ] 他人能够按说明重现关键结果。
- [ ] 用户研究尊重参与者的知情、隐私和退出选择。

### 24.5 建议的自评方式

可以对每项能力采用四种状态：尚未验证、在指导下完成、能够独立完成、能够解释并复用。每个状态都附上证据链接。自评用于确定下一步，不必把所有方向合成一个总分。

如果希望进行作品评审，可以分别记录视觉、任务体验、工程质量和原创表达的优点、问题与下一步。不同作品的重点不同，评审标准应在开始前约定。

### 24.6 常见问题的定位方法

| 观察到的问题 | 优先检查 | 可尝试的修改 |
| --- | --- | --- |
| 页面显得拥挤 | 内容分组、行长、间距、信息密度 | 重组层级、分区、展开次要内容 |
| 页面显得空 | 内容价值、视觉重心、版式比例 | 补足必要信息、调整构图与图像 |
| 很多组件却缺少整体感 | 字体、色彩、圆角、素材与节奏 | 建立统一规则并检查跨页应用 |
| 画面很炫但不好用 | 主任务、导航、动效时机 | 调整强调、保留控制、明确状态 |
| 三维画面像塑料 | 材质、灯光、环境、色彩流程 | 分项检查粗糙度、反射与光照 |
| 动画出现跳变 | 数据状态、布局、中断处理 | 明确状态转换与可取消行为 |
| 低端设备卡顿 | 主线程、绘制、粒子、纹理与后处理 | 测量瓶颈并做质量分级 |
| 用户不知道下一步 | 标签、反馈、任务顺序 | 增加具体操作与结果说明 |
| 改一个页面影响很多地方 | 组件边界、令牌与隐式依赖 | 明确接口与变更范围 |
| AI 多次修改仍不满意 | 目标、参考、内容与验收描述 | 给出具体观察并分项迭代 |
