# 产品运营与增长进阶全景手册

> 从完成一次活动，到设计用户从认识产品到长期使用的完整路径，再到让增长建立在真实价值与用户信任之上。  
> 版本：1.0 · 整理日期：2026-10-25  
> 适用对象：希望让产品被更多人用起来的开发者与产品经理、准备转向运营或增长岗位的工程师（包括独立开发者），以及希望系统提升的在职运营与增长从业者。

产品运营负责让用户发现、理解并持续使用产品：把新用户带到产品里，帮助他们尽快体验到价值，在合适的时候提醒他们回来，组织内容、活动与社区，让产品与用户之间的关系持续下去。增长岗位（增长产品、增长工程、增长运营）则用实验的方法，系统地改进获客、激活、留存与变现。

增长最常见的误区，是把它理解为“想办法让数字上涨”。拉新补贴、强制分享、诱导点击可以让数字短期上涨，却会透支用户的信任，甚至触碰法律的底线。可持续的增长建立在产品真实的价值之上：先确认留下来的用户确实从产品中获益，再把这种价值传递给更多合适的人。

本手册先建立角色坐标，然后讲解用户与价值、生命周期与增长模型、获客与渠道、激活与新手引导、留存与触达、增长实验、活动与内容运营；随后进入社区、变现与定价、风控与反作弊、AI 与运营、信任与合规；最后说明运营与开发者的协作，并用求职季的增长计划演示一次完整的增长工作。

主线是：**确认产品的真实价值 → 设计用户生命周期 → 找到合适的获客渠道 → 让新用户尽快体验价值 → 建立留存与召回 → 用实验驱动改进 → 守住用户信任与合规底线。**

不同公司中，运营的职责范围差异很大：有的偏用户与内容，有的偏活动与渠道，有的与市场、销售、客户成功的职责交叉。本手册描述产品运营与增长的职责与方法；D1—D6 分级是学习组织方式，不对应任何职级体系。文中的数字均为示意，不能作为行业基准。

## 第一篇：角色定位与能力坐标

<a id="ch01"></a>

### 01 产品运营与增长负责什么

#### 01.1 运营的常见分工

| 分工 | 主要工作 | 关注的结果 |
| --- | --- | --- |
| 用户运营 | 用户分群、生命周期管理、触达与召回 | 激活率、留存率、活跃度 |
| 内容运营 | 内容的供给、质量与分发 | 内容消费与互动、内容带来的留存 |
| 活动运营 | 策划与执行活动 | 活动带来的增量用户与行为 |
| 社区运营 | 社区规则、氛围与用户共创 | 社区健康度、优质内容的比例 |
| 渠道运营 | 获客渠道的拓展与评估 | 获客规模、成本与质量 |
| 增长 | 用实验系统地改进关键环节 | 北极星指标与输入指标的持续改进 |

#### 01.2 主要产出与质量标准

| 产出 | 用途 | 好的标准 |
| --- | --- | --- |
| 用户分群与生命周期设计 | 对不同用户采取不同的运营动作 | 分群基于需求与行为，动作与阶段对应 |
| 增长模型 | 找到影响结果的关键环节 | 能用数据说明各环节的贡献 |
| 实验与复盘记录 | 积累可靠的经验 | 有假设、有对照、有结论 |
| 活动方案 | 在特定时间达成特定目标 | 目标明确，评估增量，风险可控 |
| 触达策略 | 在合适的时间提醒合适的用户 | 有频率控制，尊重用户的偏好 |
| 内容与社区规则 | 保证内容质量与社区氛围 | 规则清楚，执行一致 |

#### 01.3 职责边界与相邻角色

| 事项 | 运营与增长的位置 | 主要协作者 | 说明 |
| --- | --- | --- | --- |
| 产品方向与功能 | 提供用户反馈与机会 | 产品经理主导 | 见[《产品经理》](01-产品经理.md) |
| 指标与实验分析 | 提出问题，使用结论 | 数据分析师 | 见[《数据分析师与产品分析师》](16-数据分析师与产品分析师.md) |
| 新手引导与触达界面 | 提出目标与内容 | 设计师、内容设计师 | 见[《内容设计师》](07-内容设计师.md) |
| 活动与触达的系统 | 提出需求，参与验收 | 开发者 | 见 15 章 |
| 风控与反作弊 | 提出规则需求 | 安全工程师、风控团队 | 见[《安全工程师》](12-安全工程师.md) |
| 已付费客户的成功 | 协作 | 客户成功 | 见[《客户成功与技术支持》](20-客户成功与技术支持.md) |

几组容易混淆的角色：

- **运营与市场**：市场侧重品牌、传播与获取潜在用户的注意；运营侧重用户进入产品之后的体验与关系。两者在获客环节交叉。
- **增长与运营**：增长更强调用实验和数据系统地改进关键环节，常由产品、工程与分析组成团队；运营更强调日常对用户、内容与活动的经营。
- **运营与客户成功**：面向企业客户的产品中，客户成功负责已付费客户的使用效果与续约；运营更多面向大量的个人用户。

**本章练习**：列出所在团队过去一个季度的运营动作，按上表的分工归类，并为每一项写出它想影响的指标，以及是否有证据说明它确实产生了影响。

### 02 能力坐标：横向分支与纵向深度

#### 02.1 十个横向分支

1. **用户洞察**：用户分群、需求理解与价值判断。
2. **增长模型**：生命周期、漏斗与回路、关键环节的识别。
3. **获客**：渠道拓展、渠道评估、搜索与内容、邀请与推荐。
4. **激活**：价值时刻、新手引导与早期体验。
5. **留存与触达**：留存分析、触达策略、召回与频率控制。
6. **实验**：假设、优先级、实验设计与知识积累。
7. **活动与内容**：活动策划、内容供给与分发、复盘。
8. **社区**：社区规则、氛围、用户共创与内容治理。
9. **变现**：付费模式、定价、试用与转化。
10. **信任与风控**：反作弊、伦理底线、合规与用户权益。

#### 02.2 六级纵向深度

| 深度 | 能力表现 | 典型证据 |
| --- | --- | --- |
| D1 理解与协助 | 执行既定的运营动作，整理数据与反馈 | 执行记录、用户反馈整理 |
| D2 独立完成 | 独立负责一个活动、渠道或触达策略，并评估效果 | 活动方案与复盘、实验记录 |
| D3 负责结果 | 负责一个生命周期阶段或一个关键指标的持续改进 | 指标改进记录、增长模型 |
| D4 系统与跨团队 | 协调产品、工程、分析等团队推动增长计划 | 跨团队增长路线、实验体系 |
| D5 方法与机制 | 建立组织的增长方法、实验流程与运营规范 | 增长流程、知识库、培训 |
| D6 创新与影响 | 提出新的增长方法或模式并验证 | 公开分享、方法推广 |

#### 02.3 成长中的常见偏差

- 产品价值没有得到验证，就大量投入获客。
- 只看活动期间的数字，不评估活动的真实增量与之后的回落。
- 触达越来越频繁，用户越来越反感。
- 用补贴换来的用户质量很差，补贴一停就离开。
- 不做实验，用前后对比证明自己的工作有效。
- 为了数字使用误导或强迫用户的设计。

## 第二篇：核心工作方法

<a id="ch03"></a>

### 03 用户与价值：增长的起点

#### 03.1 先确认价值

留存差的产品，获客越多，流失也越多。在大规模投入获客之前，先确认：有没有一群用户持续使用产品？他们从产品中得到了什么？这些用户有什么共同点？

一个常用的检验方法来自增长实践者 Sean Ellis：询问活跃用户“如果不能再使用这个产品，你会有多失望”。他的经验是，回答“非常失望”的用户超过约 40% 时，产品通常已较好地满足了一群用户的需求。First Round Review 的文章介绍了 Superhuman 怎样用这个问题分析用户、改进产品。[B01](#ref-b01) 这是经验参考而不是严格标准，更重要的是分析“非常失望”的用户是谁、看重什么。

#### 03.2 用户分群

按需求与行为分群，通常比只按年龄、地区等人口属性分群更有用。例如求职平台的学生用户可以分为：

| 分群 | 需求 | 典型行为 |
| --- | --- | --- |
| 方向明确的求职者 | 快速改进简历并投递 | 上传简历后立即分析，频繁搜索岗位 |
| 方向不明确的探索者 | 了解适合自己的方向 | 浏览岗位与能力画布，较少投递 |
| 临时需求者 | 处理一次具体的申请 | 集中使用一两次后离开 |

不同分群的价值时刻、留存方式与运营动作都不同。

#### 03.3 价值时刻与核心行为

价值时刻是用户第一次真正体验到产品价值的时刻，例如第一次看到对自己简历有用的修改建议。核心行为是与长期留存最相关的行为。找到它们的方法：比较留存与流失用户在早期行为上的差异，再通过访谈与实验验证因果关系，而不是只依赖相关分析。

#### 03.4 北极星指标

北极星指标概括产品为用户创造的核心价值，增长工作围绕它展开。指标体系的设计方法见[《数据分析师与产品分析师》第 04 章](16-数据分析师与产品分析师.md#ch04)。

**本章练习**：访谈或调查一批活跃用户，统计“非常失望”的比例，按分群比较；找出一个候选的价值时刻，比较达到与未达到这一时刻的用户的留存差异，并说明这一差异是否足以证明因果关系。

<a id="ch04"></a>

### 04 用户生命周期与增长模型

#### 04.1 生命周期漏斗

常用的海盗指标（AARRR）把用户生命周期分为五个环节：获客、激活、留存、推荐、变现。它帮助团队看清用户在哪个环节流失最多。

| 环节 | 关键问题 | 示例指标 |
| --- | --- | --- |
| 获客 | 用户从哪里来 | 各渠道的新访客与注册数 |
| 激活 | 新用户是否体验到价值 | 注册后 7 天内完成首次分析的比例 |
| 留存 | 用户是否持续使用 | 按注册周统计的第 4 周留存率 |
| 推荐 | 用户是否带来新用户 | 邀请发出数、被邀请者的注册率 |
| 变现 | 用户是否愿意付费 | 付费转化率、续费率 |

#### 04.2 漏斗与回路

漏斗描述用户的单向流动，每一步都有流失；回路描述产出重新成为投入的循环。例如：学生完成分析并分享自己的能力画布，看到分享的同学注册并完成分析，又产生新的分享。回路让增长可以复利，但前提是每一轮的产出足够，并且分享对用户本身有价值。

#### 04.3 生命周期阶段与运营动作

| 阶段 | 用户状态 | 运营动作 |
| --- | --- | --- |
| 新用户 | 刚注册，尚未体验价值 | 新手引导，帮助到达价值时刻 |
| 成长期 | 已体验价值，使用尚不稳定 | 介绍更多功能，建立使用习惯 |
| 成熟期 | 稳定使用 | 深度功能、社区参与、推荐 |
| 沉默期 | 使用明显减少 | 了解原因，提供新的价值 |
| 流失 | 长时间未使用 | 有针对性的召回，或尊重用户的离开 |

#### 04.4 增长模型

把北极星指标拆成可以分别改进的环节，估算每个环节的改进能带来多少结果。例如（示意）：

```text
每周完成修改并投递的学生数
  = 每周新访客 × 注册率 × 激活率 × 激活后投递率
  + 老用户中的每周活跃数 × 活跃用户投递率
```

模型帮助判断优先改进哪个环节：如果激活率很低，增加访客只会放大流失。

**本章验收**：为一个产品建立增长模型，用实际数据填入各环节的数值，找出改进潜力最大的两个环节，并说明判断依据。

### 05 获客与渠道

#### 05.1 渠道类型

| 渠道 | 特点 |
| --- | --- |
| 自然搜索 | 用户主动寻找，意图明确；见效慢，可持续 |
| 内容 | 通过有价值的内容吸引用户；需要持续投入 |
| 口碑与社交分享 | 信任度高；依赖产品本身的价值 |
| 邀请与推荐 | 成本可控；需要防止作弊 |
| 应用商店 | 移动应用的主要入口；受商店规则影响 |
| 合作 | 例如与学校就业指导部门合作；需要长期维护关系 |
| 付费投放 | 见效快，可控；成本高，停止投放后流量随之消失 |

#### 05.2 评估渠道

不只看获客数量与成本，还要看渠道带来的用户质量：激活率、留存率与长期价值。一个获客成本低、但用户几乎不留存的渠道，实际成本可能最高。评估时按渠道分群比较这些指标。

#### 05.3 搜索与内容

搜索引擎带来的用户通常意图明确。基础工作包括：让页面能被抓取与理解、为每个页面写准确的标题与描述、提供真正解决用户问题的内容。Google 的搜索引擎优化入门指南介绍了这些基础做法。[B02](#ref-b02) 不要使用堆砌关键词、批量生成低质量页面等手段，它们损害用户体验，也违反搜索引擎的规则。

#### 05.4 邀请与推荐

- 让分享本身对用户有价值，例如分享自己的能力画布给同学参考。
- 激励要与真实的价值挂钩，例如被邀请者完成首次分析后双方获得额外的分析次数。
- 设计防作弊规则：限制同一设备与支付方式的重复奖励，识别批量注册。
- 不强迫用户分享才能使用基本功能。

#### 05.5 付费投放与归因

付费投放需要归因：判断用户来自哪个渠道。归因模型各有局限，用户可能在多个渠道接触产品，隐私保护的加强也让跨渠道追踪越来越受限。重要的投放决策可以用分地区或分时段的对照实验估计真实的增量。

**本章练习**：比较三个获客渠道的获客成本、激活率与第 4 周留存率，计算每个渠道获得一个留存用户的成本，提出渠道预算的调整建议。

<a id="ch06"></a>

### 06 激活与新手引导

#### 06.1 定义激活

激活是新用户第一次体验到产品价值的标志，通常用一个具体的行为定义，例如“注册后 7 天内完成首次简历分析并查看至少 3 条建议”。定义要与长期留存相关，并能被团队直接改进。

#### 06.2 缩短到达价值的路径

- 列出新用户从注册到价值时刻的每一个步骤，删除或推迟不必要的步骤。
- 推迟非必要的信息收集，例如先让用户体验分析，再请他完善资料。
- 提供示例数据或模板，让用户在没有准备好时也能体验。
- 让空状态告诉用户下一步做什么，而不是只显示“暂无数据”。

#### 06.3 引导的原则

- 在用户需要时提供帮助，而不是一开始展示一长串说明。
- 引导可以跳过，并且之后还能找到。
- 引导内容简洁具体，告诉用户能得到什么。

新手引导的交互与文案设计见[《UX／交互设计师》](05-UX交互设计师.md)与[《内容设计师》](07-内容设计师.md)。

**本章验收**：画出新用户到达价值时刻的完整路径，标出每一步的转化率，提出两项缩短路径的改进，并用实验验证其中一项的效果。

<a id="ch07"></a>

### 07 留存、召回与触达

#### 07.1 读懂留存曲线

按用户首次使用的时间分组（同期群），观察每组在之后各周仍在使用的比例。曲线逐渐趋于平稳，说明有一部分用户形成了稳定使用；曲线持续下降到接近零，说明产品还没有留住用户。比较不同时期的同期群，可以判断产品改进是否提升了留存。

#### 07.2 提升留存

- 加强核心价值：让用户每次使用都有收获。
- 与用户的自然节奏结合：例如求职季前后的不同需求。
- 适度的提醒：在用户可能需要时提醒，而不是按固定频率打扰。
- 减少流失原因：分析流失用户的最后行为与反馈。

#### 07.3 触达渠道与规则

| 渠道 | 适合 | 注意事项 |
| --- | --- | --- |
| 站内消息 | 用户在产品内时的提示 | 避免遮挡主要操作 |
| 推送通知 | 及时、与用户相关的提醒 | 需要用户授权，过多会被关闭 |
| 邮件 | 较长的内容、周期性的总结 | 提供明显的退订方式 |
| 短信 | 重要且时间敏感的通知 | 营销短信需要取得用户同意并提供退订方式 |

触达的基本规则：

- **相关**：内容与用户的状态和需求相关。
- **频率控制**：设置每个用户在一段时间内接收触达的上限，各渠道统一计算。
- **偏好设置**：让用户选择接收哪些类型的消息、通过哪些渠道。
- **方便退订**：营销邮件提供一键退订。RFC 8058 定义了邮件一键退订的技术方式，一些大型邮箱服务商已要求批量发件人支持。[B03](#ref-b03)
- **区分通知与营销**：账号安全、交易结果等通知与营销内容分开，不借通知之名发送营销内容。

#### 07.4 召回

先区分流失原因：需求已经满足（例如已经找到工作）、产品没有解决问题、体验受挫、被其他产品替代。需求已满足的用户，可以在下一次需要时提醒，而不是反复打扰；对因体验受挫而离开的用户，先修复问题，再告诉他们变化。

**本章验收**：画出最近 8 个同期群的留存曲线，判断留存是否在改善；设计一套触达策略，包括触发条件、内容、渠道、频率上限与退订方式，并在上线后统计退订率与带来的回访。

<a id="ch08"></a>

### 08 增长实验

#### 08.1 实验流程

1. **收集想法**：来自数据分析、用户研究、客服反馈与竞品观察。
2. **写出假设**：如果做某项改动，预期哪个指标变化多少，原因是什么。
3. **排序**：常用影响、信心与容易程度（ICE）三项打分，作为排序的参考。
4. **实验**：设计对照实验，确定主要指标、护栏指标与样本量。
5. **学习**：无论结果如何，都记录结论与原因，更新对用户的理解。

#### 08.2 实验的统计要求

增长实验同样需要遵守对照实验的要求：事先确定指标与样本量、检查分组比例、不在中途反复查看结果并提前停止。具体方法见[《数据分析师与产品分析师》第 07 章](16-数据分析师与产品分析师.md#ch07)。

#### 08.3 流量不足时

小产品的流量往往不足以检测小幅度的变化。可以选择影响较大的改动进行实验、延长实验时间、使用更敏感的指标，或者结合用户访谈与前后对比，并承认证据较弱。

#### 08.4 积累知识

建立实验记录库，记录每个实验的假设、设计、结果与结论。失败的实验同样有价值：它们说明哪些想法不成立，避免团队重复尝试。

**本章验收**：为一个关键环节提出 10 个实验想法，用 ICE 排序，完成排名第一的实验，按模板写出结论，并加入实验记录库。

<a id="ch09"></a>

### 09 活动与内容运营

#### 09.1 评估活动的真实效果

活动期间的数字上涨，可能只是把之后的行为提前了，活动结束后随之回落。评估活动时：

- 比较活动期间与之后一段时间的总体效果，而不只看活动期间。
- 尽量保留一部分用户不参加活动作为对照，估计真实的增量。
- 统计活动带来的用户的后续留存，而不只是参与人数。

#### 09.2 活动设计

- **目标**：明确要影响的指标与预期幅度。
- **规则**：清楚、无歧义，提前确认规则文本与例外情况。
- **预算与风控**：设定总预算与单人上限，识别作弊行为。
- **技术准备**：预估流量峰值，确认系统容量、限流与降级方案；涉及奖励发放的活动，确认资金或权益的防重与对账（见 15 章）。
- **开关与回滚**：活动可以随时暂停，出现问题时能够撤回。

#### 09.3 内容运营

内容运营关注内容从哪里来（自己生产、用户贡献、合作方提供）、质量如何保证（审核标准、事实核查）、怎样到达需要它的用户（分类、推荐、搜索）。求职平台的内容可以包括简历写作指南、岗位能力解读、面试经验分享。

#### 09.4 复盘

活动结束后复盘：目标是否达成、真实增量是多少、成本是多少、出现了哪些问题、哪些经验可以复用。复盘的结论记录到知识库中。

**本章练习**：为一次活动写出完整方案，包括目标、规则、预算、风控、技术准备与对照组设计；活动结束后按模板复盘，计算真实增量与单位成本。

## 第三篇：专项与进阶

<a id="ch10"></a>

### 10 社区与用户共创

#### 10.1 社区的价值与代价

社区能带来用户之间的互助、优质的用户内容与归属感，但也需要持续投入：规则制定、内容审核、冲突处理与氛围维护。没有治理的社区很快会被广告、灌水与冲突占据。

#### 10.2 社区规则与治理

- 公开、清楚的社区规则，说明允许与禁止的行为。
- 一致的执行：相同的违规得到相同的处理。
- 分级的处理措施：提醒、删除内容、限制功能、封禁账号。
- 申诉途径与处理时限。
- 用户生成内容的审核要遵守适用的法规与平台规则，涉及违法内容的处理流程由法务确认。

#### 10.3 用户共创

邀请资深用户参与内容贡献、产品测试与新用户帮助。认可他们的贡献，但避免让少数用户承担本应由团队承担的工作，也要注意他们分享的内容是否准确。

**本章练习**：为一个社区起草社区规则与分级处理措施，抽取 100 条近期内容按规则评估，统计需要处理的比例与类型。

<a id="ch11"></a>

### 11 变现与定价基础

#### 11.1 常见的付费模式

| 模式 | 做法 | 注意事项 |
| --- | --- | --- |
| 免费增值 | 基础功能免费，高级功能付费 | 免费部分要有真实价值，付费部分要有明确差异 |
| 免费试用 | 一段时间内免费使用完整功能 | 试用结束前清楚提醒，不默认自动扣费而不告知 |
| 按量付费 | 按使用量计费 | 用量与费用清楚可查，设置上限提醒 |
| 订阅 | 按周期付费 | 取消方式与订阅方式一样方便 |

#### 11.2 定价

定价基于用户获得的价值、成本与替代方案。定价测试要谨慎：同一时间对相似用户展示不同价格，可能引起不公平的感受与合规问题，需要与法务确认。

#### 11.3 转化

付费转化的关键是让用户在体验到价值之后，清楚地了解付费能得到什么。付费页面说明价格、周期、自动续费规则与取消方式。权益与计费的后端设计见[《后端进阶全景手册》第 29 章](../技术方向/后端进阶全景手册.md#ch29)。

**本章练习**：梳理产品的付费路径，从第一次看到付费入口到完成付费，标出每一步可能让用户困惑或感到被误导的地方，并提出改进。

<a id="ch12"></a>

### 12 风控与反作弊

#### 12.1 常见的作弊行为

- 批量注册账号领取新人奖励。
- 自己邀请自己，骗取邀请奖励。
- 利用规则漏洞重复领取优惠。
- 用脚本刷取排行榜或活动积分。

#### 12.2 防护思路

- 在活动设计阶段就考虑作弊方式，规则中写明违规的处理方式。
- 奖励与真实的价值行为挂钩，而不是与容易伪造的行为挂钩。
- 设置单人与总体的奖励上限。
- 识别异常：同一设备或网络的大量账号、异常的行为速度、相似的注册信息。
- 延迟发放奖励，在发放前审核异常。

#### 12.3 平衡误伤

风控规则过严会误伤正常用户。为被拦截的用户提供申诉途径，统计误伤率，定期调整规则。风控的技术实现与安全团队协作完成，见[《安全工程师》](12-安全工程师.md)。

**本章练习**：为一次邀请活动列出至少五种作弊方式，为每种设计识别与处理规则，并估计规则可能误伤的正常用户比例。

<a id="ch13"></a>

### 13 AI 与运营

#### 13.1 用 AI 辅助运营工作

AI 工具可以帮助起草文案、整理用户反馈、生成内容初稿、辅助分析用户分群。需要注意：

- 生成的内容需要人工核对事实与语气，尤其是涉及规则、价格与承诺的内容。
- 不把用户的个人信息发送给未经评估的外部服务。
- 生成合成内容需要遵守标识要求。《人工智能生成合成内容标识办法》自 2025 年 9 月 1 日起施行。[B04](#ref-b04) 具体义务由法务确认。

#### 13.2 个性化

根据用户的行为推荐内容与触达时机，可以提高相关性。同时要让用户能够关闭个性化推荐（见 14 章），并避免利用用户的弱点诱导消费。

#### 13.3 AI 功能的运营

运营 AI 功能时，帮助用户形成准确的预期：说明功能能做什么、不能做什么，提供使用示例，收集用户对结果的反馈，并把反馈传递给负责模型的团队。AI 功能的度量见[《数据分析师与产品分析师》第 13 章](16-数据分析师与产品分析师.md#ch13)。

**本章练习**：用 AI 工具起草一组触达文案，人工核对后记录修改的内容与原因，总结哪些类型的内容必须由人确认。

<a id="ch14"></a>

### 14 信任、伦理与合规

#### 14.1 不使用操纵性设计

操纵性设计（常被称为“暗模式”）通过误导或施压让用户做出违背自身意愿的选择，例如虚假的倒计时与库存提示、默认勾选的付费选项、难以找到的取消入口。美国联邦贸易委员会的报告系统整理了这类设计及其危害。[B05](#ref-b05) 它们可能带来短期的数字，却会损害信任，并可能违反消费者保护的相关规定。

#### 14.2 营销触达与个性化

- 营销触达需要取得用户同意，并提供便捷的退订方式。
- 我国《个人信息保护法》规定，通过自动化决策方式向个人进行信息推送、商业营销，应当同时提供不针对其个人特征的选项，或者向个人提供便捷的拒绝方式。[B06](#ref-b06)
- 《互联网信息服务算法推荐管理规定》要求向用户提供不针对其个人特征的选项，或者便捷的关闭算法推荐服务的选项。

#### 14.3 广告与宣传

宣传内容真实、准确，不夸大功能与效果。在互联网上发布的广告应当具有可识别性，《互联网广告管理办法》自 2023 年 5 月 1 日起施行。涉及“保证录取”“百分之百通过”等绝对化或承诺性的表述，应当避免。

#### 14.4 特殊人群

面向学生的产品可能涉及未成年人，需要遵守未成年人保护的相关要求。具体义务由法务确认。

**本章练习**：审查产品的注册、付费、取消与触达流程，列出可能被认为具有误导性或操纵性的设计，并提出替代方案。

## 第四篇：协作、实战与成长

<a id="ch15"></a>

### 15 与开发者的协作接口

#### 15.1 运营需要的工程能力

| 能力 | 作用 |
| --- | --- |
| 配置化 | 活动规则、文案、开关不需要发版即可调整 |
| 用户分群与触达 | 按条件圈选用户，按渠道触达，统一频率控制 |
| 实验平台 | 分组、开关、结果分析 |
| 埋点 | 记录关键行为，见[《数据分析师与产品分析师》第 05 章](16-数据分析师与产品分析师.md#ch05) |
| 权益与奖励 | 发放、防重、对账、撤回 |
| 风控接口 | 识别异常账号与行为 |

#### 15.2 活动需求应包含的内容

开发者需要的不只是“做一个活动页面”，而是：活动目标与时间、规则与例外、预估的流量峰值、预算与单人上限、奖励的发放方式与防重要求、暂停与回滚的方式、需要的数据与报表、风控规则。这些信息决定了系统的容量设计与资金安全。

#### 15.3 共同避免的问题

- 活动上线当天才发现流量超出系统容量。
- 奖励重复发放，造成资金或权益损失。
- 规则文本与系统实现不一致。
- 活动结束后才发现需要的数据没有记录。

<a id="ch16"></a>

### 16 开发者怎样借用运营与增长方法

#### 16.1 独立开发者

- 先找到一小群真正需要产品的用户，深入了解他们，而不是急于获取大量用户。
- 选择一两个与目标用户匹配的渠道，持续投入，而不是在所有渠道浅尝辄止。
- 在产品中建立反馈入口，亲自回复早期用户。
- 用简单的增长模型找到最需要改进的环节。
- 每周查看激活与留存，而不只看注册数。

#### 16.2 外包与交付项目

客户提出“做一个活动系统”“做一个会员体系”时，先了解背后的运营目标与玩法，把运营规则转化为可配置的系统，而不是把规则写死在代码里。交付时提供运营后台的使用说明，并说明系统的容量与风控能力的边界。

#### 16.3 技术背景的常见偏差

- 认为“产品好自然会有用户”，不投入获客与运营。
- 用技术手段大量群发消息，忽视用户感受与合规要求。
- 设计邀请机制时没有考虑作弊。
- 只做功能，不做新手引导与空状态。

<a id="ch17"></a>

### 17 贯穿实战：求职季的增长计划

本章以求职平台为例，展示一次完整的增长工作。数字均为示意。

#### 17.1 目标与诊断

- **目标**：在秋季求职季的 8 周内，把“每周完成修改并投递的学生数”提升 30%。
- **诊断**：访客到注册的转化率尚可；注册后 7 天内完成首次分析的比例只有 35%；完成分析的用户中，第 4 周留存约 40%，说明激活后的价值得到了验证。结论：优先改进激活，再扩大获客。

#### 17.2 计划

| 环节 | 动作 | 指标 |
| --- | --- | --- |
| 激活 | 注册后直接进入简历上传，资料完善推迟到分析之后；提供示例简历体验分析 | 7 天激活率 |
| 留存 | 投递截止日期提醒；分析结果更新后通知（用户可选择接收） | 第 4 周留存、退订率 |
| 获客 | 与学校就业指导部门合作开展简历讲座；发布简历写作指南 | 各渠道的激活用户数 |
| 推荐 | 用户可分享能力画布；被邀请者完成首次分析后双方获得额外分析次数 | 邀请带来的激活用户数 |

#### 17.3 实验与结果

1. **新手路径实验**：调整后的路径使 7 天激活率从 35% 提升到 44%，护栏指标（分析完成率、投诉）无明显变化，全量上线。
2. **提醒实验**：截止日期提醒使第 4 周留存提升约 3 个百分点，退订率低于 2%，保留；每周总结邮件没有显著效果，停止。
3. **邀请计划**：上线后第一周发现同一设备批量注册领取奖励，暂停奖励发放，增加设备与行为识别规则，并改为被邀请者完成首次分析后再发放奖励。

#### 17.4 复盘

8 周后目标指标提升约 26%，未达到 30%。主要原因：校园讲座的排期晚于预期。经验：激活改进的效果最大且可持续；邀请奖励必须在上线前完成防作弊设计；校园渠道需要提前一个学期规划。

#### 18.5 检查清单

- [ ] 在投入获客之前，确认已有一群用户持续获得价值。
- [ ] 增长模型说明了各环节的贡献，优先改进瓶颈环节。

## 附录 C：常见误读、内容边界与修订记录

### C.1 常见误读与准确表述

| 容易误读的说法 | 更准确的表述 |
| --- | --- |
| 增长就是拉新 | 留存差时拉新只会放大流失，先确认价值与留存 |
| 活动期间数字上涨说明活动成功 | 需要评估真实增量与活动后的回落 |
| 触达越多，回访越多 | 过度触达会导致退订、关闭通知与流失 |
| 获客成本越低的渠道越好 | 需要结合用户的激活与留存评估 |
| 补贴能带来忠实用户 | 补贴带来的用户可能在补贴停止后离开 |
| 前后对比就能证明效果 | 需要对照实验或考虑其他因素的影响 |
| 用户没反对就是同意 | 营销触达需要取得同意并提供便捷的退订 |
| 倒计时与库存提示能提升转化 | 虚假的紧迫感属于操纵性设计，会损害信任 |
| AI 生成的文案可以直接发布 | 需要人工核对事实、语气与承诺 |
