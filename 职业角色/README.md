# 职业角色全景

> 一个想独立做产品、接外包、带项目的开发者，需要认识的 26 种专业角色，以及对应的进阶手册。  
> 版本：1.0 · 整理日期：2026-10-25  
> 适用对象：已经能完成前后端开发、做过自己的产品或外包项目，希望理解项目中各种专业分工的开发者；也适合准备转岗、需要选择方向的工程师。

对于一个想独立做产品、接外包、带项目的开发者来说，产品经理只是需要了解的其中一种角色。用户需求、体验设计、质量保障、上线运行、数据分析和客户交付，都有相应的专业分工。认识这些职业，能帮助你判断：**一个项目遇到的问题，应该从哪个专业角度解决。**

不同公司的岗位名称和分工会有重叠，小团队里一个人也可能承担多种职责。本系列为每种角色写了一册进阶手册，说明它负责什么、怎样工作、与开发者怎样协作，以及开发者可以借用哪些方法。这一页是整个系列的入口。

## 1 为什么开发者需要认识这些角色

一个功能能否成功，很少只取决于代码。以求职平台的 AI 简历分析为例，调用模型成功只是其中一个环节：

| 需要回答的问题 | 主要的专业视角 | 对应手册 |
| --- | --- | --- |
| 先解决学生的哪个求职问题？怎样算成功？ | 产品经理 | [01 产品经理](01-产品经理.md) |
| 学生为什么卡在修改简历这一步？ | 用户研究员 | [02 用户研究员](02-用户研究员.md) |
| 简历、岗位、投递记录之间的流程与规则是什么？ | 业务分析师 | [03 业务分析师](03-业务分析师.md) |
| 建议是否符合真实的招聘实践？ | 领域专家 | [04 领域专家](04-领域专家.md) |
| 学生能否看懂建议、知道下一步做什么？ | 交互设计师、内容设计师 | [05](05-UX交互设计师.md)、[07](07-内容设计师.md) |
| 建议是否有依据？效果怎样评测？ | 算法与机器学习工程师 | [18 算法与机器学习工程师](18-算法与机器学习工程师.md) |
| 学生是否真的完成了修改并投递？ | 数据分析师 | [16 数据分析师与产品分析师](16-数据分析师与产品分析师.md) |
| 分析过程是否太慢？出故障时怎么办？ | 运维工程师与 SRE | [13 运维工程师与 SRE](13-运维工程师与SRE.md) |
| 简历中的个人信息是否安全？ | 安全工程师 | [12 安全工程师](12-安全工程师.md) |

你不必成为每一种专家，但需要能够识别：当前的问题属于哪个专业领域，什么时候自己可以借用这个领域的方法，什么时候需要相应的专业人员参与。

## 2 五组角色与对应手册

下面按项目中要回答的问题，把 26 种角色分为五组，另有一个交叉方向。表格中的说明是常见的职责划分，不同公司会有差异。英国政府的数字与数据职业能力框架对其中许多角色的职责与技能有系统的描述，可作为参照。[B01](#ref-b01)

### 2.1 决定“为谁做、做什么”

| 角色 | 主要负责什么 | 开发者理解它有什么用 |
| --- | --- | --- |
| [01 产品经理](01-产品经理.md) | 理解用户与业务目标，确定产品方向、功能优先级和成功标准 | 判断功能是否值得做，控制需求范围 |
| [02 用户研究员](02-用户研究员.md) | 通过访谈、观察、可用性研究等了解用户行为与困难 | 发现用户实际需要什么，避免只凭想象开发 |
| [03 业务分析师](03-业务分析师.md) | 梳理业务流程、规则、角色、信息和约束，把模糊的需求具体化 | 把客户的一句话转化为可以实现、可以验收的需求 |
| [04 领域专家](04-领域专家.md) | 提供某个行业的实际知识，例如招聘、教育、物流、财务 | 检查系统规则是否符合真实业务 |

产品经理平衡用户与业务需求、推动产品产生价值；用户研究为决策提供证据；业务分析师特别关注业务的运作、规则与变化的影响。三者经常合作。

### 2.2 决定“用户能否看懂、顺利使用”

| 角色 | 主要负责什么 | 对开发的直接影响 |
| --- | --- | --- |
| [05 UX／交互设计师](05-UX交互设计师.md) | 信息结构、操作流程、页面状态、反馈和异常处理 | 明确用户怎样完成任务，以及失败后怎么办 |
| [06 UI／视觉设计师](06-UI视觉设计师.md) | 字体、颜色、布局、图标、视觉层次和界面规范 | 提升页面的清晰度、统一性和视觉表现 |
| [07 内容设计师／UX 文案](07-内容设计师.md) | 按钮名称、提示、错误信息、引导说明等 | 让用户知道当前发生了什么、下一步怎么做 |
| [08 服务设计师](08-服务设计师.md) | 设计跨页面、跨渠道、跨人员的完整服务过程 | 连接软件功能、人工支持和线下流程 |
| [09 无障碍专家](09-无障碍专家.md) | 识别不同能力的用户使用产品时的障碍 | 指导键盘操作、读屏支持、焦点顺序等实现 |

这些职责可能合并在“产品设计师”岗位中，也可能分别设置。英国政府服务手册说明了服务团队中各个角色的分工，服务设计尤其关注完整的旅程，范围可以延伸到数字产品之外。[B02](#ref-b02)

可以这样区分：**视觉设计改善呈现，交互设计改善操作，内容设计改善理解，服务设计改善整个办事过程。**

### 2.3 把系统做稳、长期维护

| 角色 | 主要负责什么 | 开发者值得学习的能力 |
| --- | --- | --- |
| [10 软件架构师与技术负责人](10-软件架构师与技术负责人.md) | 系统边界、技术取舍、关键设计和技术风险 | 比较方案，解释为什么这样设计，控制复杂度 |
| [11 测试工程师与测试开发](11-测试工程师与测试开发.md) | 测试分析、异常场景、自动化验证和质量证据 | 从边界、并发、失败路径和真实场景检查实现 |
| [12 安全工程师](12-安全工程师.md) | 威胁分析、权限边界、漏洞治理和安全设计 | 提前识别越权、数据泄露、依赖风险等问题 |
| [13 运维工程师与 SRE](13-运维工程师与SRE.md) | 系统运行、监控、容量、故障响应和可靠性改进 | 让服务可观察、可恢复，并能承受实际负载 |
| [14 平台工程师与研发效能](14-平台工程师与研发效能.md) | 为开发团队建设工具、环境、流水线和自助能力 | 把重复操作自动化，让开发与交付更稳定 |
| [15 数据库工程师／DBA](15-数据库工程师DBA.md) | 数据库的性能、运行管理、备份恢复和迁移 | 理解数据系统的容量、故障与变更风险 |

运维与 SRE 的侧重点因公司而异。Google 的 SRE 实践强调用软件工程的方法处理运行问题。[B03](#ref-b03) 平台工程则着重为开发者提供工具与工作流程，云原生计算基金会的平台白皮书说明了内部平台的目标与组成。[B04](#ref-b04)

你还可能看到 **DevOps 工程师**这一岗位名称。DevOps 首先是一种开发与运维协作的文化与实践；具体岗位可能侧重流水线、基础设施自动化或运行保障，需要看实际的职责。本系列在[《运维工程师与 SRE》第 13 章](13-运维工程师与SRE.md#ch13)专门讨论 DevOps。

### 2.4 判断“有没有效果、为什么没有效果”

| 角色 | 主要负责什么 | 与开发如何配合 |
| --- | --- | --- |
| [16 数据分析师与产品分析师](16-数据分析师与产品分析师.md) | 指标、使用行为、转化漏斗和实验分析 | 确定要记录哪些事件，定位用户在哪一步流失 |
| [17 数据工程师](17-数据工程师.md) | 数据采集、清洗、建模、数据管道和质量管理 | 让分析与业务功能使用可靠的数据 |
| [18 算法与机器学习工程师](18-算法与机器学习工程师.md) | 推荐、搜索、预测、模型训练与推理、大模型应用 | 把算法效果、性能和工程约束结合起来 |
| [19 产品运营与增长](19-产品运营与增长.md) | 用户触达、使用引导、反馈收集、留存与增长实验 | 提出运营需要的系统能力，反馈用户的实际使用情况 |
| [20 客户成功与技术支持](20-客户成功与技术支持.md) | 帮助客户用好产品、排查问题、持续获得价值 | 把使用障碍和客户需求反馈到产品与开发中 |

数据分析、数据工程和机器学习是不同的专业方向；在实际项目中，它们会共同参与数据产品与智能功能的建设。

### 2.5 让项目能交付、让团队能持续工作

| 角色 | 主要负责什么 | 对开发者有什么价值 |
| --- | --- | --- |
| [21 项目经理与交付经理](21-项目经理与交付经理.md) | 范围、进度、依赖、资源、风险和交付协调 | 接外包时管理需求变化、里程碑和验收 |
| [22 解决方案架构师](22-解决方案架构师.md) | 把客户需求、现有系统和技术能力组合为可落地的方案 | 理解企业项目中的集成、选型与方案沟通 |
| [23 实施与交付工程师](23-实施与交付工程师.md) | 配置、部署、数据迁移、系统对接、培训和验收 | 解决软件进入客户真实环境后的问题 |
| [24 技术写作者与文档工程师](24-技术写作者与文档工程师.md) | 接口文档、接入指南、操作手册和故障说明 | 让别人能够使用、接入、维护你的系统 |
| [25 研发经理与工程经理](25-研发经理与工程经理.md) | 团队能力、人员成长、工程流程和持续交付 | 理解团队怎样分工、培养成员和处理组织问题 |

交付管理关注产品与服务的交付，以及清除阻碍团队推进的问题。**产品经理更侧重产品的价值与优先级，项目／交付经理更侧重组织交付**，两者会协作，也可能由同一个人承担。

### 2.6 交叉方向：前沿部署工程师

[26 前沿部署工程师（FDE）](26-前沿部署工程师FDE.md)结合客户沟通、数据处理、方案设计和实际编码，直接进入客户的业务场景解决问题，并把共性需求反馈给产品。这一角色因 Palantir 而广为人知，它的博客介绍了产品工程师与前沿部署工程师两类角色的区别。[B05](#ref-b05) 近年来，许多 AI 公司也设立了这一岗位，帮助企业客户把模型落地到具体业务中。具体的编码、沟通与出差比例因公司和岗位而异。

## 3 一个项目从想法到运行，谁在参与

| 阶段 | 主要参与的角色 | 典型产出 |
| --- | --- | --- |
| 发现机会 | 产品经理、用户研究员、领域专家、数据分析师 | 机会与假设、研究发现、数据洞察 |
| 定义需求 | 产品经理、业务分析师、领域专家 | 问题与成功标准、流程与规则、验收标准 |
| 设计体验 | 交互设计师、视觉设计师、内容设计师、服务设计师、无障碍专家 | 流程与状态、界面规范、文案、服务蓝图 |
| 方案与架构 | 软件架构师、解决方案架构师、安全工程师、数据库工程师 | 架构决定、客户方案、威胁模型、数据模型 |
| 开发与测试 | 开发者、测试工程师、平台工程师 | 代码、测试与质量证据、流水线 |
| 部署与上线 | 运维工程师与 SRE、实施与交付工程师、项目经理 | 发布与切换计划、上线检查、培训 |
| 运行与保障 | 运维工程师与 SRE、数据库工程师、技术支持 | 监控与告警、值班、复盘、备份恢复 |
| 度量与改进 | 数据分析师、数据工程师、算法工程师、产品经理 | 指标体系、实验、数据管道、模型改进 |
| 增长与运营 | 产品运营与增长、内容设计师 | 生命周期运营、触达策略、增长实验 |
| 客户与交付 | 客户成功、解决方案架构师、实施工程师、前沿部署工程师、技术写作者 | 上手计划、方案、文档、价值报告 |
| 团队与组织 | 研发经理、项目经理、平台工程师 | 团队章程、交付节奏、工程文化 |

小团队里，这些阶段可能都由同一个人完成。即使如此，按阶段检查一遍“这一步应该由什么专业视角把关”，也能发现很多容易遗漏的问题。

## 5 开发者优先吸收的五种角色

对于已有前后端开发经验、做过自己的产品或外包项目的开发者，建议优先吸收以下五种角色的工作方法。它们可以直接用在正在做的项目里。

| 角色 | 具体做法 | 从哪里开始读 |
| --- | --- | --- |
| **产品经理** | 每个功能先写清楚目标用户、问题、优先级和成功标准 | [01 册第 04 章](01-产品经理.md#ch04)、[第 07 章](01-产品经理.md#ch07)、[第 16 章](01-产品经理.md#ch16) |
| **业务分析师** | 整理流程、权限、状态变化、异常情况和验收条件 | [03 册第 06 章](03-业务分析师.md#ch06)、[第 09 章](03-业务分析师.md#ch09)、[第 17 章](03-业务分析师.md#ch17) |
| **UX／交互设计师** | 在编码前走通完整的操作流程，包括加载、空状态和失败状态 | [05 册第 05 章](05-UX交互设计师.md#ch05)、[第 16 章](05-UX交互设计师.md#ch16) |
| **测试工程师** | 主动设计让功能失败的场景，验证边界和恢复行为 | [11 册第 03 章](11-测试工程师与测试开发.md#ch03)、[第 04 章](11-测试工程师与测试开发.md#ch04)、[第 16 章](11-测试工程师与测试开发.md#ch16) |

## 附录 A：手册结构与深度分级

### A.1 每册的结构

| 部分 | 内容 |

### A.2 六级深度

| 深度 | 含义 |
| --- | --- |
| D1 理解与协助 | 理解基本概念，能在他人指导下完成部分工作 |
| D2 独立完成 | 能独立完成一项完整的工作 |
| D3 负责结果 | 对一个领域或一类问题的长期结果负责 |
| D4 系统与跨团队 | 处理跨系统、跨团队的复杂问题 |
| D5 方法与机制 | 为组织建立方法、工具与机制 |
| D6 创新与影响 | 提出新的方法并产生更大范围的影响 |

D1—D6 是学习的组织方式，帮助你判断自己在每个方向上处于什么位置，不对应任何公司的职级体系。

### A.3 贯穿案例

各册使用同一组案例，便于互相对照：

- **求职平台**：学生上传简历，获得 AI 简历分析、岗位匹配建议，并在“职业能力画布”上整理目标、技能与学习任务；企业版帮助连锁企业的门店筛选应聘者。
- **外包交付**：为一家拥有 120 家门店的连锁企业交付招聘管理系统，覆盖需求分析（03 册）、方案设计（22 册）、项目交付（21 册）与实施上线（23 册）。

案例中的数字、指标和规则都是示意，不代表真实的产品数据。全系列的写作约定见[写作规范](../写作规范.md)。
